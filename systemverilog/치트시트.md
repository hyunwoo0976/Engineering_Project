# SystemVerilog 검증 치트시트

## 큰 그림: 왜 SV로 검증?
객체(class)로 **"수만 개 테스트를 한 틀로"** 만들어 랜덤 생성. 손으로 수만 줄 안 쓰고, 설계도 1개 + 제약으로 자동 대량 생성.

## 🗺️ 모든 코드는 이 3부분 뼈대
```systemverilog
// ── ① 물건(Transaction) = 데이터 설계도 ──
class Tr;
    rand bit [7:0] data;                       // 랜덤 필드
    constraint c { data inside {[1:100]}; }    // 규칙
    function void print(); $display("%h", data); endfunction
endclass

// ── ② 사람(Component) = 일꾼 ──
class Generator;
    mailbox #(Tr) mb;                                   // 벨트(Tr을 실음)
    function new(mailbox #(Tr) mb); this.mb = mb; endfunction  // 벨트 받기
    task run;
        repeat(N) begin
            Tr t = new();  t.randomize();  mb.put(t);   // 만들고→랜덤→벨트에
        end
    endtask
endclass

// ── ③ Top = 연결 + 실행 ──
module Top;
    mailbox #(Tr) mb = new();
    Generator gen = new(mb);
    Consumer  con = new(mb);
    initial begin fork gen.run(); con.run(); join $finish; end
endmodule
```
**새 문법 나오면 → 이 지도의 어디(물건/사람/Top)에 꽂히는지만 보면 됨.**

## 문법 지도 (어디에 들어가나)
| 문법 | 뜻 | 위치 |
|---|---|---|
| `rand` | 랜덤화 대상 필드 | 물건 |
| `constraint c {}` | 규칙 (선언적, `{ }` 씀 — begin/end 아님!) | 물건 |
| `x inside {[a:b]}` | 범위/집합 제약 | 물건 |
| `x dist {v:=w}` | 값별 비율(가중치) | 물건 |
| `A -> B` | A면 B (조건부 제약) | 물건 |
| `if(a){...}else{...}` | 조건부 제약 (constraint 안에선 `{}`) | 물건 |
| `randc` | 순환 랜덤(같은 객체 반복 시 안 겹침) | 물건 |
| `bit[7:0] arr[]` | 동적 배열(크기 런타임 결정) | 물건 |
| `solve A before B` | A 먼저 풀기 | 물건 |
| `post_randomize()` | randomize 직후 자동 실행(체크섬 등) | 물건 |
| `extends`/`virtual`/`super.` | 상속/다형성/부모호출 | 물건 |
| `function void f()` | 반환없는 함수(버튼) | 물건/사람 |
| `task run` | 시간 걸리는 작업(#delay 가능) | 사람 |
| `mailbox #(Tr) mb` | Tr을 실어나르는 벨트 | 사람/Top |
| `mb.put(x)`/`mb.get(x)` | 벨트에 넣기/빼기(비면 대기) | 사람 |
| `fork...join` | 동시 실행 | Top |
| `$fatal(1,"msg")` | 즉시 종료(1=종료시 시간·위치 출력) | 사람 |

## 핵심 3줄
- **class=설계도, object(new())=그 설계도로 만든 실체**
- **상속=IS-A**(자식은 부모 + 추가). 예: 기본로봇 → 전투로봇(기본+무기). ※팔/다리는 "부품"이라 상속 아님
- **물건=데이터, 사람=벨트+run, Top=연결+fork**
