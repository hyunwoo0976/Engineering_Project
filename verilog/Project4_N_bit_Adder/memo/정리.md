## 3. 동작 원리

### 캐리 체인

```verilog
wire [N:0] c;
assign c[0] = cin;              // 외부 캐리 입력

generate
    for (i=0; i<N; i=i+1) begin : adder_gen
        calculate_adder FA(
            .x(a[i]), .y(b[i]),
            .cin(c[i]),          // 아래 자리에서
            .sum(sum[i]),
            .cout(c[i+1])        // 위 자리로
        );
    end
endgenerate

assign cout = c[N];
```

`c`를 `[N:0]`으로 한 칸 크게 잡아 캐리를 배열로 표현했다.
`c[0] = cin`이므로 **외부 캐리 입력이 실제로 동작한다** — 여러 개를 이어 붙여
더 넓은 가산기를 만들 수 있다.

### 캐리 전파

```
c[0] → FA[0] → c[1] → FA[1] → c[2] → FA[2] → c[3] → FA[3] → c[4]=cout
```

각 FA는 아래 자리의 캐리가 확정되어야 자기 계산을 끝낼 수 있다.
→ 최악의 경우 캐리가 LSB에서 MSB까지 **N단을 거쳐 흐른다.** 이것이 리플 캐리의 지연 특성.

### 계산 예

```
a = 1111 (15), b = 0001 (1), cin = 0

비트0: 1+1+0 = 0, c1=1     ← 캐리 발생
비트1: 1+0+1 = 0, c2=1     ← 전파
비트2: 1+0+1 = 0, c3=1     ← 전파
비트3: 1+0+1 = 0, c4=1     ← 전파

sum = 0000, cout = 1       (16 = 10000₂)
```

캐리가 4단 전부를 통과하는 **최악 지연 케이스**다.

## 4. 핵심 코드

### Project 3과의 차이 — `cin`이 실제로 쓰인다

```verilog
assign c[0] = cin;      // Project 4 — 포트를 그대로 체인 시작값으로
```

Project 3의 감산기는 `ci[0] = 1'b1;`로 하드코딩해 `cin` 포트가 죽어 있었다.
여기서는 순수 가산기이므로 `cin`이 의미를 갖는다.

### 파라미터로 폭 분리

```verilog
module N_bit_adder #(parameter N=4)( ... );
...
N_bit_adder #(.N(4)) uut( ... );
```

`N`만 바꾸면 8비트·32비트로 확장된다. 내부 `generate` 루프와 `c` 배열 폭이 함께 따라간다.

## 5. 검증 방법

`$monitor`로 값 변화 출력. 총 19케이스 (초기 1 + 루프 16 + 추가 2).

### 실행 결과

| # | a | b | cin | sum | cout | 비고 |
|---|---|---|---|---|---|---|
| 0 | 0 | 0 | 0 | 0 | 0 | 초기값 |
| 1~16 | i | 15−i | 0 | **15** | **0** | 루프 (i=0..15) |
| 17 | 15 | 1 | 0 | 0 | 1 | 캐리 4단 전파 |
| 18 | 15 | 15 | 1 | 15 | 1 | cin 사용, 31 = `11111` |

### 루프가 캐리 전파를 전혀 밟지 않는다

`b = 15 − a` 인데, 4비트에서 **`15 − a`는 `~a`와 같다.**

```
a = 0101 (5)  →  b = 15-5 = 10 = 1010 = ~0101
```

따라서 모든 비트 위치가 `0+1` 또는 `1+0` 조합이 되어

```
sum 비트 = 1,  carry = 0
```

**캐리가 한 번도 발생하지 않는다.** 16개 케이스가 서로 다른 입력 패턴이지만,
결과가 전부 `sum=15, cout=0`으로 동일하고 캐리 체인은 계속 0이다.

캐리 전파를 실제로 검증한 것은 **케이스 17, 18 두 개**뿐이다.
다행히 17번(`1111 + 0001`)이 최악 지연 케이스라 핵심은 덮였다.

## 6. 배운 것 / 이후 연결

| 개념 | 이후 사용처 |
|---|---|
| **캐리 체인을 배열로 표현** | Project 10 CLA, 감산기 |
| **리플 캐리의 O(N) 지연** | CLA를 쓰는 이유의 근거 |
| **`generate`로 하드웨어 복제** | 파이프라인 레지스터, LZD, 배럴 시프터 |
| **파일 목록으로 타 프로젝트 모듈 참조** | 공용 모듈 관리 |
| **입력 개수 ≠ 검증 범위** | 케이스 수가 아니라 무엇을 밟았는지가 중요 |

### 남은 개선 사항

- 루프의 `b = 15 - a`를 바꿔 캐리 전파가 발생하는 조합을 넣는다.
  예: `b = a` (모든 비트에서 캐리 발생 가능), 또는 랜덤 입력
- 자동 판정 추가. 기대값을 Verilog 연산으로 만들 수 있다.
  ```verilog
  if ({cout, sum} !== (a + b + cin)) $display("[FAIL] a=%d b=%d cin=%b", a, b, cin);
  ```
- N=8, N=32로 인스턴스화해 파라미터화가 실제로 동작하는지 확인
