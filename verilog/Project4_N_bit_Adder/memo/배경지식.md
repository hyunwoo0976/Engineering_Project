# Project 4 — 배경지식

주제: **리플 캐리 가산기, 캐리 전파 지연, 고속 가산기 구조, 임계 경로**

---

## 1. 리플 캐리 가산기 (RCA)

전가산기 N개를 캐리로 이어 붙인 가장 단순한 구조.

```
    a3 b3      a2 b2      a1 b1      a0 b0
     │  │       │  │       │  │       │  │
   ┌─▼──▼─┐   ┌─▼──▼─┐   ┌─▼──▼─┐   ┌─▼──▼─┐
c4─┤ FA3  ├c3─┤ FA2  ├c2─┤ FA1  ├c1─┤ FA0  ├─c0(cin)
   └──┬───┘   └──┬───┘   └──┬───┘   └──┬───┘
    sum3       sum2       sum1       sum0
```

| 항목 | 값 |
|---|---|
| 면적 | O(N) — FA N개 |
| **지연** | **O(N)** — 캐리 체인이 임계 경로 |
| 구조 | 규칙적, 배선 단순 |

### 왜 "리플(ripple)"인가

캐리가 LSB에서 MSB로 **물결처럼 순차적으로 번진다.**
각 FA는 아래 자리의 캐리가 확정되기 전에는 자기 `sum`을 확정할 수 없다.

---

## 2. 지연 분석

### 임계 경로

전가산기 하나의 캐리 경로 지연을 `t_c`라 하면:

```
전체 지연 ≈ N × t_c  +  t_sum
```

`c0`에서 `c_N`까지 N개의 FA를 통과해야 하고, 마지막에 `sum` 비트가 확정된다.

### 이 프로젝트 구조의 실제 지연

`calculate_adder`는 반가산기 2개를 직렬로 쓴다.

```
cin → HA2의 XOR/AND → c2 → OR → cout
```

캐리 경로에 **XOR/AND 1단 + OR 1단**이 있으므로, 게이트 지연을 `t_g`라 하면
FA당 캐리 지연이 약 `2·t_g`.

4비트에서는 `8·t_g` 정도. 32비트면 `64·t_g`가 되어 감당하기 어렵다.

### 최악 케이스 입력

캐리가 전 구간을 통과하는 입력이 최악 지연을 만든다.

```
1111 + 0001 = 10000
```

이 프로젝트 테스트벤치의 17번 케이스가 정확히 이것이다.
반면 루프의 `a + ~a` 조합은 캐리가 아예 발생하지 않아 **최선 케이스**다.

> 타이밍 검증에서는 최악 케이스 패턴을 의도적으로 넣어야 한다.
> 평균적인 입력만 넣으면 실제 임계 경로가 드러나지 않는다.

## 3. 고속 가산기 구조

RCA의 O(N) 지연을 개선하는 방법들.

| 구조 | 지연 | 면적 | 핵심 아이디어 |
|---|---|---|---|
| **RCA** (리플 캐리) | O(N) | 최소 | 캐리를 순차 전파 |
| **CLA** (캐리 룩어헤드) | **O(log N)** | 큼 | G/P로 캐리를 병렬 계산 |
| **Carry-Select** | O(√N) | 약 2배 | 캐리 0/1 두 경우를 미리 계산해 MUX 선택 |
| **Carry-Skip** | 개선 | 중간 | 블록 전체가 전파면 건너뛰기 |
| **Carry-Save** | O(1)* | — | 캐리를 즉시 더하지 않고 따로 보관 (다입력 덧셈용) |

\* Carry-Save는 최종 합을 얻으려면 마지막에 일반 가산기가 한 번 필요하다.

### CLA — G/P 분리

Project 2에서 정리한 개념이 여기서 쓰인다.

```
G_i = a_i · b_i          (generate — cin과 무관하게 캐리 생성)
P_i = a_i ^ b_i          (propagate — 들어온 캐리를 통과)

c_{i+1} = G_i + P_i · c_i
```

`G`와 `P`는 **`cin`을 기다리지 않고** 모든 비트에서 동시에 계산할 수 있다.
이를 펼치면 캐리를 직접 구할 수 있다.

```
c1 = G0 + P0·c0
c2 = G1 + P1·G0 + P1·P0·c0
c3 = G2 + P2·G1 + P2·P1·G0 + P2·P1·P0·c0
c4 = G3 + P3·G2 + P3·P2·G1 + P3·P2·P1·G0 + P3·P2·P1·P0·c0
```

각 캐리가 `c0`에서 **직접** 계산되므로 체인을 기다리지 않는다.

**대가**: 비트 수가 늘면 항의 개수와 팬인이 폭발한다.
그래서 실제로는 4비트 블록 CLA를 만들고 그 블록들을 다시 계층적으로 묶는다
(블록 단위 G/P → 그룹 G/P). 이것이 O(log N)이 나오는 구조다.

Project 10의 FPU가 48비트 가수를 더할 때 이 CLA를 쓴다.

### Carry-Select 발상

`cin`이 0인 경우와 1인 경우를 **둘 다 미리 계산**해 두고, 실제 `cin`이 도착하면 MUX로 고른다.

```
       ┌── adder (cin=0) ──┐
블록 ──┤                    ├── MUX ── 결과
       └── adder (cin=1) ──┘      ▲
                                  cin
```

면적이 약 2배가 되지만, 캐리를 기다리는 시간이 MUX 지연 하나로 줄어든다.
Project 2의 §3 ③에서 언급한 "MUX 기반 전가산기"가 이 발상의 씨앗이다.

## 4. 왜 여전히 RCA를 배우는가

실무의 32/64비트 가산기는 RCA를 쓰지 않는다. 그럼에도:

1. **모든 고속 구조의 기준점**이다. "RCA보다 얼마나 빠른가"로 비교한다
2. **면적이 최소**다. 지연이 문제되지 않는 저속·저전력 회로에서는 여전히 최적
3. **합성 도구가 알아서 바꿔준다.** `a + b`라고 쓰면 도구가 타이밍 제약에 맞춰
   RCA/CLA/기타 구조를 선택한다. 그 선택을 이해하려면 구조를 알아야 한다
4. 캐리 체인이 **임계 경로**라는 개념 자체가 타이밍 분석의 기본이다

## 5. 임계 경로와 동작 주파수

**임계 경로(critical path)** — 회로에서 가장 오래 걸리는 조합 논리 경로.

```
최대 동작 주파수 f_max = 1 / (t_critical + t_setup + t_clk-to-q)
```

가산기에서 임계 경로는 거의 항상 **캐리 체인**이다.
파이프라인 CPU에서 ALU가 임계 경로에 놓이는 경우가 많은 이유이기도 하다.

Project 10에서 포워딩 MUX가 ALU 앞에 추가되면 임계 경로가
`포워딩 MUX + ALU`가 되어 조금 길어진다. 그래도 stall로 사이클을 버리는 것보다 이득이다.

## 6. 오버플로와 캐리 (N비트에서)

| | 조건 | 대상 |
|---|---|---|
| **캐리** | `cout = 1` | 무부호 범위 초과 |
| **오버플로** | `c_N ^ c_{N-1}` | 부호 있는 범위 초과 |

`c_N`은 MSB에서 나가는 캐리, `c_{N-1}`은 MSB로 들어오는 캐리다. 둘이 다르면 오버플로.

4비트 예:

| 연산 | 결과 | cout | overflow | 해석 |
|---|---|---|---|---|
| `0111 + 0001` | `1000` | 0 | **1** | 7+1 = −8 (부호 있는 오버플로) |
| `1111 + 0001` | `0000` | **1** | 0 | 15+1 = 16 (무부호 캐리) / −1+1 = 0 (부호는 정상) |

같은 회로가 두 해석을 동시에 지원한다. 어느 플래그를 볼지는 명령어가 결정한다.

이 프로젝트는 `cout`만 출력하고 오버플로는 계산하지 않는다.
→ Project 5의 ALU에서 다룬다.

## 7. 검증 관점 — 케이스 수와 커버리지

이 프로젝트 테스트벤치가 좋은 사례다.

| | 값 |
|---|---|
| 테스트 케이스 수 | 19개 |
| 서로 다른 입력 조합 | 18개 |
| **캐리 전파를 밟은 케이스** | **2개** |

루프의 16개는 `a + ~a` 조합이라 캐리가 발생하지 않는다.
캐리 체인 배선이 잘못되어 있어도 그 16개는 전부 통과한다.

**"몇 개 넣었나"가 아니라 "무엇을 밟았나"** 가 검증 범위를 결정한다.
회로의 핵심 동작(여기서는 캐리 전파)을 겨냥한 케이스가 있는지 확인해야 한다.

### 4비트라면 전수 검증이 가능하다

입력이 `a`(4) + `b`(4) + `cin`(1) = 9비트 → **2⁹ = 512 케이스**.
이 정도는 전수로 돌릴 수 있고, 기대값도 `a + b + cin`으로 한 줄에 만들 수 있다.

```verilog
for (i=0; i<512; i=i+1) begin
    {cin, a, b} = i;
    #10;
    if ({cout, sum} !== (a + b + cin)) $display("[FAIL] ...");
end
```

비트폭이 커지면(32비트 → 2⁶⁵) 불가능해지므로 제약 랜덤으로 넘어가야 한다.

## 8. 용어 정리

| 용어 | 뜻 |
|---|---|
| **RCA** | Ripple Carry Adder. 캐리를 순차 전파. 지연 O(N) |
| **CLA** | Carry-Lookahead Adder. G/P로 캐리 병렬 계산. O(log N) |
| **Carry-Select** | 캐리 0/1 두 경우를 미리 계산해 MUX로 선택 |
| **Carry-Save** | 캐리를 즉시 더하지 않고 별도 보관. 다입력 덧셈에 사용 |
| **G / P** | generate(`a·b`) / propagate(`a^b`) |
| **임계 경로** | 가장 느린 조합 경로. 최대 주파수를 결정 |
| **최악 케이스 패턴** | 임계 경로를 실제로 활성화하는 입력 (`1111+0001`) |
| **캐리 vs 오버플로** | 무부호 범위 초과 / 부호 있는 범위 초과 |
