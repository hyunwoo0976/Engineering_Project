## 1. 조합 논리 vs 순차 논리

| | 조합 논리 (Combinational) | 순차 논리 (Sequential) |
|---|---|---|
| 출력 결정 요인 | **현재 입력만** | 현재 입력 + **과거 상태** |
| 기억 소자 | 없음 | 있음 (래치, 플립플롭) |
| 클럭 | 불필요 | 보통 필요 |
| 표현 | 진리표, 부울식 | 상태 전이도, FSM |
| 예 | 게이트, MUX, 가산기, 디코더 | 레지스터, 카운터, FSM |

이 프로젝트는 **조합 논리**만 다룬다. 기억이 없으므로 입력을 넣으면 (전파 지연 후) 즉시 출력이 정해진다.
→ Project 6·7에서 순차 논리로 넘어간다.

## 2. 부울 대수 기본 법칙

최소화에 실제로 쓰이는 것들:

| 법칙 | 식 |
|---|---|
| 교환 | A+B = B+A, A·B = B·A |
| 결합 | (A+B)+C = A+(B+C) |
| **분배** | A·(B+C) = A·B + A·C |
| **상보** | A + ~A = **1**, A · ~A = **0** |
| 항등 | A+0 = A, A·1 = A |
| 지배 | A+1 = 1, A·0 = 0 |
| 멱등 | A+A = A, A·A = A |
| **흡수** | A + A·B = A, A·(A+B) = A |
| 이중부정 | ~(~A) = A |
| **드모르간** | ~(A+B) = ~A·~B, ~(A·B) = ~A+~B |

### 이 프로젝트에서 쓴 것

```
(~x)·y·z + (~x)·y·(~z)
= (~x)·y·(z + ~z)      ← 분배 (역방향, 공통항 묶기)
= (~x)·y·1             ← 상보
= (~x)·y               ← 항등
```

**핵심 패턴**: `A·B + A·~B = A` — 어떤 변수가 두 항에서 **참·거짓 양쪽으로 나타나면 그 변수는 소거**된다.
카르노 맵에서 두 칸을 묶는 것과 정확히 같은 연산이다.

### 드모르간의 실무 의미

CMOS에서는 NAND·NOR가 AND·OR보다 **트랜지스터가 적다** (AND = NAND + NOT).
드모르간으로 AND-OR 형태를 NAND-NAND로 바꿔 게이트 수를 줄이는 것이 표준 기법이다.

```
A·B + C·D  =  ~( ~(A·B) · ~(C·D) )   ← NAND 3개로 구현 가능
```

## 3. 표준형 — SOP와 POS

| 형태 | 뜻 | 구조 | 예 |
|---|---|---|---|
| **SOP** (Sum of Products) | 곱의 합 | AND들을 OR로 | `(~x)y + xz` |
| **POS** (Product of Sums) | 합의 곱 | OR들을 AND로 | `(x+y)·(~x+z)` |

- **최소항(minterm)** — 모든 변수가 한 번씩 나타나는 AND 항. 진리표에서 출력이 1인 행 하나에 대응
- **최대항(maxterm)** — 모든 변수가 나타나는 OR 항. 출력이 0인 행에 대응

이 프로젝트의 원래 식은 **최소항 3개의 SOP** 형태였고, 최소화 후에도 SOP다.

**어느 쪽이 유리한가**: 출력이 1인 행이 적으면 SOP, 0인 행이 적으면 POS가 항 수가 적다.

## 4. 카르노 맵 (K-map)

부울식을 **눈으로** 최소화하는 도구. 3변수면 2×4 격자.

이 회로를 K-map으로 그리면 (행 = x, 열 = yz, **그레이 코드 순서** 00-01-11-10):

```
        yz=00  01   11   10
  x=0  │  0 │  0 │  1 │  1 │     ← (~x)·y 묶음 (오른쪽 두 칸)
  x=1  │  0 │  1 │  1 │  0 │     ← x·z 묶음 (가운데 두 칸)
```

- `x=0` 행에서 `y=1`인 두 칸(11, 10)을 묶으면 → **(~x)·y**
- `z=1`인 열에서 `x=1`인 두 칸(01, 11)을 묶으면 → **x·z**

→ `f = (~x)·y + x·z` (코드의 최소화 결과와 일치)

**왜 그레이 코드 순서인가**: 인접한 칸이 **한 비트만** 다르게 배치해야, 묶을 때 그 비트가 소거된다. 이게 K-map이 동작하는 원리다.

**묶는 규칙**
- 1의 개수가 2ⁿ개(1, 2, 4, 8...)인 직사각형만 묶을 수 있다
- 크게 묶을수록 항이 짧아진다 (변수가 더 많이 소거됨)
- 겹쳐 묶어도 된다 (멱등법칙 A+A=A 때문에 손해가 없다)
- **상하좌우가 이어져 있다** (원통형) — 맨 왼쪽과 맨 오른쪽 열이 인접

4변수를 넘어가면 사람이 하기 어려워, 실무에서는 **Quine-McCluskey 알고리즘**이나 합성 도구가 처리한다.

## 5. ★ 이 회로는 2:1 MUX다

`f = (~x)·y + x·z` 를 `x`로 나눠 보면:

| x | f |
|---|---|
| 0 | y |
| 1 | z |

**select가 `x`, 데이터가 `y`·`z`인 2:1 멀티플렉서.**

### MUX가 중요한 이유

MUX는 "선택"이라는 개념의 하드웨어 구현이고, 디지털 설계 전반의 기본 블록이다:

| 용도 | 예 |
|---|---|
| 연산 선택 | ALU에서 add/sub/and/or 중 하나 고르기 |
| 데이터 경로 선택 | PC 소스 (순차 / 분기 / 점프) |
| 포워딩 | 레지스터 값 vs MEM 값 vs WB 값 |
| 소프트웨어의 if/case | 합성되면 MUX가 된다 |

Verilog에서 `if`, `case`, `? :` 는 조합 회로 문맥에서 전부 **MUX로 합성**된다.
"어떤 값을 고를지"를 쓰면 도구가 MUX를 만들어 준다.

### N:1 MUX
- 데이터 입력 N개 → select 비트 ⌈log₂N⌉개
- 2:1 → 1비트, 4:1 → 2비트, 8:1 → 3비트

Project 5의 ALU가 `mode[1:0]`로 4가지 연산을 고르는 것이 4:1 MUX다.

## 6. 모델링 추상화 수준

Verilog는 같은 회로를 여러 수준으로 기술할 수 있다.

| 수준 | 기술 방법 | 예 | 특징 |
|---|---|---|---|
| **스위치 레벨** | 트랜지스터 (`nmos`, `pmos`) | — | 거의 안 씀 |
| **게이트 레벨** | 프리미티브 (`and`, `or`, `not`) | `combinational_logic.v` | 구조를 명시. verbose |
| **데이터플로우(RTL)** | `assign` + 연산자 | `standard_logic.v` | **실무 표준** |
| **동작 레벨** | `always`, `if`, `case` | Project 5 이후 | 알고리즘 기술 |

### 왜 게이트 레벨을 배우나

실무에서 직접 쓰지는 않는다. 그런데:
1. **합성 결과가 게이트라는 것을 이해**해야 한다. `assign` 한 줄이 몇 개의 게이트가 되는지 감이 있어야 면적·지연을 예측할 수 있다
2. **합성 도구의 출력**(netlist)이 게이트 레벨이다. 게이트 레벨 시뮬레이션(GLS)으로 검증하는 단계가 실제로 있다
3. 라이브러리 셀 매핑, STA를 이해하는 기반이 된다

> **RTL(Register Transfer Level)**: 레지스터 사이의 데이터 이동과 그 사이의 조합 논리를 기술하는 수준. 실무 설계의 기본 단위이며, 합성 도구의 입력이다.

## 7. 왜 최소화가 중요한가

| 지표 | 영향 |
|---|---|
| **면적** | 게이트가 적으면 칩 면적이 작다 → 원가 절감 |
| **지연(delay)** | 경로가 짧으면 임계 경로가 짧아져 동작 주파수가 올라간다 |
| **전력** | 게이트가 적고 스위칭이 적으면 동적 전력이 줄어든다 |
| **팬인(fan-in)** | 입력이 많은 게이트는 느리다. 3입력 AND를 2입력으로 줄이는 것에 실익이 있다 |

이 프로젝트에서 3입력 AND 2개가 사라진 것은 셋 다에 해당하는 개선이다.

### 그런데 합성 도구가 자동으로 해주지 않나?

해준다. Design Compiler, Yosys 등은 최소화·기술 매핑을 자동 수행한다.
그럼에도 배우는 이유:

1. **합성 도구가 못 고치는 구조가 있다.** 알고리즘 수준의 비효율(불필요한 상태, 과도한 비교)은 RTL을 다시 써야 한다
2. **결과를 읽어야 한다.** 면적·타이밍 리포트를 보고 원인을 짚으려면 부울 수준의 이해가 필요하다
3. **의도하지 않은 논리를 알아채려면** 내가 쓴 코드가 어떤 회로가 되는지 예측할 수 있어야 한다

## 8. 전파 지연과 글리치

조합 논리는 즉시 반응하지 않는다. 각 게이트에 **전파 지연(propagation delay)** 이 있다.

- **임계 경로(critical path)** — 입력에서 출력까지 가장 오래 걸리는 경로. 이것이 최대 동작 주파수를 결정
- **글리치(glitch)** — 경로별 지연 차이 때문에 출력이 최종값에 도달하기 전 순간적으로 잘못된 값을 내는 현상

예: `x`가 0→1로 바뀔 때 `~x` 경로는 NOT 게이트를 한 번 더 지나므로 늦게 도착한다. 그 사이 `(~x)·y`와 `x·z`가 동시에 0이 되는 순간이 생겨 `f`에 짧은 0 펄스가 나타날 수 있다.

**대응**: 조합 논리 출력을 **레지스터로 받는다**(register the output). 클럭 에지에서만 값을 잡으므로 중간 글리치는 무시된다. 이것이 동기 설계의 기본 원칙이고, Project 6·7에서 다루는 내용이다.

## 9. 용어 정리

| 용어 | 뜻 |
|---|---|
| **조합 논리** | 출력이 현재 입력만으로 결정되는 회로 |
| **최소항 / 최대항** | 진리표의 1인 행 / 0인 행에 대응하는 항 |
| **SOP / POS** | 곱의 합 / 합의 곱 표준형 |
| **K-map** | 부울식을 시각적으로 최소화하는 격자 |
| **팬인 / 팬아웃** | 게이트의 입력 개수 / 한 출력이 구동하는 입력 개수 |
| **전파 지연** | 입력 변화가 출력에 반영되기까지의 시간 |
| **임계 경로** | 가장 느린 경로. 최대 주파수를 결정 |
| **글리치** | 지연 차이로 인한 순간적 오출력 |
| **프리미티브** | Verilog 내장 게이트 (`and`, `or`, `not`, `xor`, `nand`, `nor`) |
| **RTL** | Register Transfer Level. 실무 설계 기술 수준 |
| **등가 검증** | 두 구현이 기능적으로 같은지 확인하는 검증 |
