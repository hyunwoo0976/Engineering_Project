## 기록된 오류 없음

이 프로젝트를 진행할 당시에는 오류 기록을 남기지 않았다.
git 이력(커밋 4개)과 README에도 디버깅 흔적이 없고, `img_combinational_logic_gate/`에는
정상 파형(`combinational_logic_wave.PNG`) 한 장만 있다.

> 회로가 단순해(3입력 조합 논리) 실제로 큰 문제가 없었을 가능성이 높다.
> 다만 **기록이 없다는 것과 문제가 없었다는 것은 다르다.** 이후 프로젝트부터는
> 오류가 나면 파형을 캡처하고 이 파일에 남긴다.

## 재검토에서 확인한 사항

버그는 아니지만 나중에 다시 볼 때 필요한 내용.

### R01 · README의 부울식 오타
- **[증상]** README 3행의 식이 `f=(~x)&y&z|(~x)&y&z|x&z` 로, **두 번째 항이 첫 번째와 동일**
- **[실제]** `combinational_logic.v`의 게이트 연결을 보면 두 번째 항은 `(~x)&y&~z`
  ```verilog
  and and3_1(w_and3_1, w_inv_x, y, w_inv_z);   // (~x)·y·(~z)
  ```
- **[영향]** 코드는 정상. README만 틀렸다. 다만 이 오타 때문에 최소화 과정이
  설명되지 않는다 — `z + ~z = 1`로 소거되는 것이 이 프로젝트의 핵심인데,
  두 항이 같으면 멱등법칙(A+A=A)으로 그냥 사라지는 다른 이야기가 된다
- **[조치]** README 수정 필요

### R02 · 테스트벤치에 자동 판정이 없음
- **[증상]** `combinational_logic_tb.v`가 두 구현(`f`, `f1`)을 나란히 구동하지만
  **비교 로직이 없다.** 파형을 사람이 눈으로 대조해야 한다
- **[영향]** 8케이스라 눈으로 볼 수 있어 당장은 문제가 아니다. 다만 등가 검증의 요점이
  "두 구현이 같은가"인데 그 판정을 자동화하지 않았다
- **[개선안]** 루프 안에 한 줄 추가하면 self-checking이 된다
  ```verilog
  #10;
  if (f !== f1) $display("[MISMATCH] {x,y,z}=%b : f=%b f1=%b", {a,b,c}, f, f1);
  ```
  → [검증 방법론](../../memo/검증_방법론.md)

### R03 · `$monitor` / 최종 요약 없음
- 실행해도 콘솔에 아무 출력이 없어, 시뮬레이션이 성공했는지 파형을 열어야 알 수 있다
- PASS/FAIL 카운터와 마지막 요약 한 줄이면 콘솔만 보고 판단 가능
