# Project 1 — 정리

조합 논리 회로를 **두 가지 모델링 수준**으로 구현하고, 부울 대수로 최소화한 뒤 **등가성을 검증**한 프로젝트.

---

## 1. 목표

| | |
|---|---|
| 설계 대상 | 3입력(`x`, `y`, `z`) 1출력(`f`) 조합 논리 |
| 학습 목표 | ① 부울 대수 최소화 ② 게이트 레벨 vs 데이터플로우 모델링 ③ 전수 검증 |

## 3. 동작 원리

### 원래 식 (게이트 레벨로 구현한 것)

코드의 게이트 연결을 그대로 읽으면:

| 게이트 | 입력 | 항 |
|---|---|---|
| `and3_0` | `~x`, `y`, `z` | (~x)·y·z |
| `and3_1` | `~x`, `y`, `~z` | (~x)·y·(~z) |
| `and2_0` | `x`, `z` | x·z |
| `or3_0` | 위 셋 | f |

```
f = (~x)·y·z + (~x)·y·(~z) + x·z
```

> ⚠️ **README 오타 정정**: README에는 `f=(~x)&y&z|(~x)&y&z|x&z` 로 적혀 있는데
> 두 번째 항이 첫 번째와 같다. 실제 코드는 두 번째가 `(~x)&y&~z` 다.

### 최소화 과정

```
f = (~x)·y·z + (~x)·y·(~z) + x·z
  = (~x)·y·(z + ~z)          + x·z     ← 분배법칙으로 (~x)·y 묶기
  = (~x)·y·1                 + x·z     ← 상보법칙 (z + ~z = 1)
  = (~x)·y + x·z
```

**3입력 AND 2개 + 2입력 AND 1개 + 3입력 OR** → **2입력 AND 2개 + 2입력 OR 1개**

`standard_logic.v`의 `assign f = (~x)&y | x&z;` 가 이 최소화 결과다.

### ★ 이 회로의 정체 — 2:1 멀티플렉서

최소화된 식을 `x` 기준으로 보면:

| x | f |
|---|---|
| 0 | `y` |
| 1 | `z` |

**`x`가 select, `y`·`z`가 데이터 입력인 2:1 MUX**다.
MUX는 이후 모든 프로젝트에서 반복 등장한다 (ALU 연산 선택, PC 소스 선택, 포워딩 경로 선택).

## 4. 핵심 코드

### 게이트 레벨 — 프리미티브 인스턴스화

```verilog
not inv_x(w_inv_x, x);               // not 게이트명(출력, 입력)
and and3_0(w_and3_0, w_inv_x, y, z); // and 게이트명(출력, 입력1, 입력2, ...)
or  or3_0(f, w_and3_0, w_and3_1, w_and2_0);
```

문법상 **출력이 첫 번째 인자**임에 주의. 모듈 인스턴스화의 포트 순서 규칙과 다르다.
내부 연결선을 `wire`로 직접 선언해야 하므로 길고 실수하기 쉽다.

### 데이터플로우 — 한 줄

```verilog
assign f = (~x)&y | x&z;
```

`&`가 `|`보다 우선순위가 높아 괄호 없이도 의도대로 동작하지만,
`((~x)&y) | (x&z)` 로 명시하는 편이 안전하다.

## 5. 검증 방법

### 전수 검증 (exhaustive)

```verilog
for (i = 0; i < 8; i = i+1) begin
    {a,b,c}    = i;    // uut0 입력
    {a1,b1,c1} = i;    // uut1 입력
    #10;
end
```

입력이 3비트뿐이라 **2³ = 8가지를 전부** 넣을 수 있다. 입력이 적을 때만 가능한 사치.

### 등가 검증 (equivalence check)

두 구현을 같은 입력으로 동시에 구동하고 `f`와 `f1`을 비교한다.
**최소화가 기능을 바꾸지 않았음**을 증명하는 구조다.

| `{x,y,z}` | 기대 `f` | 근거 |
|---|---|---|
| 000 | 0 | x=0 → f=y=0 |
| 001 | 0 | x=0 → f=y=0 |
| 010 | 1 | x=0 → f=y=1 |
| 011 | 1 | x=0 → f=y=1 |
| 100 | 0 | x=1 → f=z=0 |
| 101 | 1 | x=1 → f=z=1 |
| 110 | 0 | x=1 → f=z=0 |
| 111 | 1 | x=1 → f=z=1 |

## 6. 배운 것 / 이후 연결

| 개념 | 이후 사용처 |
|---|---|
| **부울 최소화** | ALU 제어 로직, 디코더 조건식 단순화 |
| **게이트 vs 데이터플로우** | 이후 모든 설계는 데이터플로우/동작 수준으로 작성 |
| **2:1 MUX 구조** | ALU_MUX, PC_MUX, 포워딩 MUX (Project 5, 10) |
| **등가 검증** | 리팩터 후 "기능이 같은지" 확인하는 사고방식 |
| **전수 검증의 한계** | 입력이 늘면 2ⁿ으로 폭발 → 제약 랜덤 검증이 필요해지는 이유 |

### 남은 개선 사항

- TB가 `f`와 `f1`을 나란히 구동하지만 비교 로직이 없어 파형을 눈으로 대조해야 한다.
  루프 안에 한 줄 추가하면 자동 판정이 된다.
  ```verilog
  if (f !== f1) $display("MISMATCH at %b : f=%b f1=%b", {a,b,c}, f, f1);
  ```
- 콘솔 출력이 없어 시뮬레이션 성공 여부를 파형을 열어야 알 수 있다. `$monitor` 또는 최종 요약 필요
