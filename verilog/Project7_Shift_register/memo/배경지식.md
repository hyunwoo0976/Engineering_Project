# Project 7 — 배경지식

주제: **래치 → 플립플롭 → 시프트 레지스터, 직렬 통신, 관측성**

---

## 1. 기억 소자의 계보

```
SR 래치 → D 래치 → D 플립플롭 → 레지스터 → 시프트 레지스터
```

각 단계가 앞 단계의 결함을 보완한다.

### SR 래치

```verilog
assign Q   = ~(R | n_Q);
assign n_Q = ~(S | Q);
```

NOR 게이트 2개를 교차 결합(cross-coupled). 가장 단순한 기억 소자.

| S | R | Q |
|---|---|---|
| 0 | 0 | **이전 값 유지** |
| 1 | 0 | 1 (set) |
| 0 | 1 | 0 (reset) |
| 1 | 1 | **금지 상태** |

`S=R=1`일 때 `Q`와 `n_Q`가 **둘 다 0**이 되어, 서로 반대여야 한다는 전제가 깨진다.
또한 그 상태에서 두 입력이 동시에 0으로 돌아가면 **어느 쪽으로 안정될지 예측 불가**(레이스).

**용도**: 물리 스위치의 바운싱 제거(디바운싱). 기계 접점의 잡음을 걸러 한 번의 깨끗한 신호로 만든다.

### D 래치

금지 상태를 구조적으로 제거한 것. 입력을 하나(`D`)로 만들고 `S = D`, `R = ~D`로 강제한다.

```verilog
always @(*) begin
    if (en) q = d;      // en이 1인 동안 계속 통과
end
```

**문제: 투명성(transparency).** `en`이 열려 있는 동안 `d`의 변화가 그대로 `q`로 새어 나간다.
그 사이 조합 논리의 글리치까지 통과한다.

### D 플립플롭

**에지 감지**로 투명성을 없앤다.

```verilog
always @(posedge clk) q <= d;
```

클럭이 올라가는 **순간**의 값만 잡는다. 그 외 시간의 입력 변화는 무시된다.

| | 래치 | 플립플롭 |
|---|---|---|
| 감지 | 레벨 (`en`이 1인 동안) | **에지** (`clk` 상승 순간) |
| 투명성 | 있음 (문제) | 없음 |
| 타이밍 분석 | 복잡 | 단순 |
| 면적 | 작음 | 큼 (보통 래치 2개) |
| 실무 | 의도적으로는 드물게 | **동기 설계의 표준** |

플립플롭은 보통 **마스터-슬레이브 구조** — 서로 반대 위상으로 열리는 래치 2개를 직렬로 놓아,
어느 순간에도 입력에서 출력으로 직통 경로가 없게 만든다.

### 레지스터 / 시프트 레지스터

- **레지스터** — 플립플롭 N개를 나란히. 병렬 저장
- **시프트 레지스터** — 플립플롭 N개를 **직렬로 연결**. 각 클럭마다 옆으로 한 칸 이동

## 2. 시프트 레지스터의 4가지 형태

입출력이 병렬인지 직렬인지에 따라 네 종류.

| 약칭 | 입력 | 출력 | 용도 |
|---|---|---|---|
| **SISO** | 직렬 | 직렬 | 지연 소자, 데이터 버퍼 |
| **SIPO** | 직렬 | 병렬 | **역직렬화** — 수신 (이 프로젝트 RX) |
| **PISO** | 병렬 | 직렬 | **직렬화** — 송신 (이 프로젝트 TX) |
| **PIPO** | 병렬 | 병렬 | 일반 레지스터 (시프트 기능 포함) |

이 프로젝트는 **PISO → 1비트 링크 → SIPO** 구조로, 직렬 통신 링크의 최소 형태다.

### 시프트 방향과 순서

```verilog
// 우측 시프트, LSB부터 전송
Q_a <= {1'b0, Q_a[W-1:1]};     assign N = Q_a[0];

// 수신: 상위에 넣고 우측으로 밀기
D_out <= {N, D_out[W-1:1]};
```

**송신이 LSB부터면 수신은 MSB 쪽에 넣어야** 순서가 보존된다.
방향이 어긋나면 비트 순서가 뒤집힌 값이 나온다.

MSB부터 보내려면 좌측 시프트(`{Q_a[W-2:0], 1'b0}`)와 `N = Q_a[W-1]`을 쓰고,
수신은 `{D_out[W-2:0], N}`이 된다.

> 실제 프로토콜에서는 이 순서가 규격으로 정해져 있다.
> UART는 LSB 우선, SPI는 보통 MSB 우선(설정 가능), I2C는 MSB 우선.

## 3. 직렬 vs 병렬 — 왜 전선을 줄이는가

| | 병렬 (32선) | 직렬 (1선) |
|---|---|---|
| 배선 수 | 32 | **1** |
| 전송 시간 | 1 클럭 | **32 클럭** |
| 핀 수 | 많음 (칩 면적·패키지 비용) | 적음 |
| 스큐(skew) | **문제** — 선마다 도착 시간이 다름 | 없음 |
| 크로스토크 | 인접 배선 간 간섭 | 적음 |

**시간을 써서 공간을 산다.** 배선·핀은 비싸고, 클럭은 상대적으로 싸다.

### 스큐가 직렬화의 진짜 이유

병렬 버스는 선마다 길이와 부하가 달라 신호 도착 시각이 어긋난다(**스큐**).
주파수를 올리면 스큐가 한 클럭 주기에 가까워져 데이터가 깨진다.

그래서 고속 인터페이스는 오히려 **직렬**을 쓴다.

| 예 | 방향 |
|---|---|
| PATA(병렬) → SATA(직렬) | 저장장치 |
| PCI(병렬) → PCIe(직렬 레인) | 확장 버스 |
| 병렬 포트 → USB | 주변기기 |

"직렬이 느리다"는 직관과 반대로, **고속에서는 직렬이 유리**하다.
레인을 여러 개 두어(PCIe x16) 대역폭을 늘리는 방식으로 확장한다.

## 4. 완료 신호와 제어 경로

이 프로젝트는 `count`와 `fin`을 **별도 `always` 블록**에 두었다.

```verilog
// 데이터 경로
always @(posedge clk or posedge reset) begin
    if (reset) Q_a <= 0;
    else if (load) Q_a <= D_in;
    else if (shift) Q_a <= {1'b0, Q_a[W-1:1]};
end

// 제어 경로
always @(posedge clk or posedge reset) begin
    if (reset) count <= 0;
    else if (load) count <= 0;
    else if (shift) count <= count + 1;
end

assign fin = (count == 32);
```

**데이터 경로와 제어 경로를 분리**하는 것이 좋은 습관이다.
- 각 블록의 역할이 명확해진다
- 제어 로직만 바꿀 때 데이터 경로를 건드리지 않는다

### 카운터 폭

32를 세려면 `count`가 0~32를 표현해야 하므로 최소 6비트(`[5:0]`, 0~63).
5비트면 0~31까지만 되어 `count==32`가 영원히 성립하지 않는다.

> 폭 계산: N개를 세려면 `⌈log₂(N+1)⌉` 비트.
> 경계값을 포함해야 하므로 `N`이 아니라 `N+1`이다.

### 완료 신호가 있으면 테스트벤치가 단순해진다

```verilog
wait(fin==1'b1);      // 32클럭을 세지 않아도 된다
```

전송 길이가 바뀌어도 테스트벤치를 고칠 필요가 없다.
Project 10의 `FPU_Valid`가 같은 역할을 한다 — 다중 사이클 연산의 결과가 준비됐음을 알리는 신호.

## 5. non-blocking이 필수인 이유

TX와 RX가 **같은 클럭 에지**에서 동작한다.

```
k번째 posedge에서:
  RX:  D_out <= {N, D_out[W-1:1]}      N = Q_a[0]
  TX:  Q_a   <= {1'b0, Q_a[W-1:1]}
```

non-blocking(`<=`)은 **모든 우변을 먼저 평가한 뒤 대입**한다.
따라서 RX는 TX가 시프트되기 **전**의 `Q_a[0]`을 읽는다. 비트가 정확히 하나씩 전달된다.

blocking(`=`)을 썼다면 블록 실행 순서에 따라
- TX가 먼저 실행되면 RX가 이미 시프트된 값을 읽어 **비트를 건너뛴다**
- RX가 먼저면 정상

즉 **시뮬레이터 스케줄링에 결과가 의존**한다. 이것이 순차 논리에 `<=`를 쓰는 규칙의 실질적 이유다.

## 6. ★ 관측성 (Observability)

이 프로젝트에서 실제로 부딪힌 문제. → [error_log E02](error_log.md)

랜덤 입력이 `4 = 0000...0100`으로 나왔다. 결과는 맞았지만 **확인할 수 없었다.**

```
D_in = 00000004  →  직렬 스트림에 '1'이 딱 한 번
```

이러면 다음을 구분할 수 없다.
- 비트가 하나씩 이동하는지
- 순서가 뒤집히지 않았는지
- 중간에 누락이 없는지

**결과가 맞은 것과 동작이 맞은 것은 다르다.**

### 검증에서 필요한 두 가지 성질

| 성질 | 뜻 |
|---|---|
| **제어성 (Controllability)** | 원하는 내부 상태를 만들 수 있는가 |
| **관측성 (Observability)** | 내부 오류가 출력까지 드러나는가 |

`D_in = 4`는 관측성이 나쁘다. 비트 대부분이 0이라 오류가 출력에 나타나지 않는다.

### 그래서 쓰는 패턴

```
A5 = 1010 0101      전이 최대
5A = 0101 1010
F0 = 1111 0000      블록 경계 확인
0F = 0000 1111
AA = 1010 1010      교대
55 = 0101 0101
DEADBEEF, CAFEBABE  눈에 띄는 마커
```

`A5A5F0F0`을 고른 것은 `1010` 반복과 `1111 0000` 블록이 섞여 있어
비트 이동과 블록 경계를 모두 확인할 수 있기 때문이다.

**랜덤이 항상 좋은 자극은 아니다.** 관측성이 필요한 구간에서는 패턴을 직접 고른다.
이것이 directed 테스트가 랜덤과 함께 필요한 또 하나의 이유다.

## 7. 시프트 레지스터의 다른 용도

직렬 통신 외에도 널리 쓰인다.

| 용도 | 원리 |
|---|---|
| **곱셈 / 나눗셈** | 좌측 시프트 = ×2, 우측 시프트 = ÷2 |
| **배럴 시프터** | 임의 비트 수를 한 클럭에 시프트 (Project 10 FPU) |
| **LFSR** | 시프트 + XOR 피드백으로 의사난수·CRC 생성 |
| **지연 라인** | N클럭 지연 (Project 10 `FPU_Check`의 in-flight 추적) |
| **직렬 ↔ 병렬 변환** | 이 프로젝트 |
| **스캔 체인 (DFT)** | 테스트를 위해 모든 플립플롭을 하나의 시프트 레지스터로 연결 |

### LFSR (Linear Feedback Shift Register)

시프트 레지스터의 특정 탭들을 XOR해 입력으로 되돌린다.

```
최대 길이 LFSR (N비트) → 2^N − 1 주기의 의사난수열
```

용도: 난수 생성, CRC 체크섬, 데이터 스크램블링, 내장 자체 테스트(BIST).
하드웨어 랜덤 자극 생성기로도 쓰인다.

### 스캔 체인

검증·테스트 관점에서 중요하다. 칩의 모든 플립플롭을 테스트 모드에서
하나의 거대한 시프트 레지스터로 연결해, 내부 상태를 직렬로 읽고 쓸 수 있게 만든다.

→ **관측성과 제어성을 하드웨어로 확보하는 기법.** DFT(Design For Test)의 핵심.

## 8. 관련 통신 프로토콜

이 프로젝트는 클럭을 공유하는 가장 단순한 형태다. 실제 프로토콜은 여기서 확장된다.

| 프로토콜 | 선 수 | 클럭 | 특징 |
|---|---|---|---|
| **이 프로젝트** | 1 (+공유 clk) | 공유 | 최소 형태 |
| **UART** | 1~2 | **없음 (비동기)** | 시작/정지 비트로 동기, 보율 사전 합의 |
| **SPI** | 3~4 | 마스터가 제공 | 전이중, 고속, 칩 선택(CS) 필요 |
| **I2C** | 2 | 마스터가 제공 | 주소 기반 다중 슬레이브, 오픈 드레인 |

**비동기(UART)의 어려움**: 클럭이 없으므로 수신 측이 데이터에서 타이밍을 복원해야 한다.
시작 비트로 정렬하고, 미리 합의한 보율로 중간 지점을 샘플링한다.
클럭 오차가 누적되면 프레임 끝에서 비트가 어긋난다.

이 프로젝트는 클럭을 공유하므로 그 문제가 없다.

## 9. 용어 정리

| 용어 | 뜻 |
|---|---|
| **SR 래치** | 교차 결합 NOR 2개. `S=R=1`이 금지 상태 |
| **D 래치** | 금지 상태 제거. 레벨 감지 → 투명성 문제 |
| **D 플립플롭** | 에지 감지. 동기 설계의 표준 |
| **마스터-슬레이브** | 반대 위상 래치 2개로 플립플롭 구성 |
| **투명성** | 래치가 열려 있는 동안 입력이 출력으로 새는 성질 |
| **SISO/SIPO/PISO/PIPO** | 직렬·병렬 입출력 조합 4종 |
| **직렬화 / 역직렬화** | 병렬 → 직렬 / 직렬 → 병렬 |
| **스큐 (skew)** | 병렬 버스에서 선별 신호 도착 시각 차이 |
| **LFSR** | 시프트 + XOR 피드백. 의사난수·CRC |
| **스캔 체인** | 모든 플립플롭을 시프트 레지스터로 연결하는 DFT 기법 |
| **제어성 / 관측성** | 내부 상태를 만들 수 있는가 / 오류가 출력에 드러나는가 |
