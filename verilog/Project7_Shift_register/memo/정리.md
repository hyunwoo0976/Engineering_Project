# Project 7 — 정리

시프트 레지스터로 **32비트 데이터를 전선 한 개로 전송**하고 다시 복원하는 직렬 통신 링크.
래치 → 플립플롭 → 시프트 레지스터로 올라가며 순차 논리를 정리한 프로젝트.

---

## 1. 목표

`src_latch/요구사항`에 적어둔 것:

> `a`로 32비트의 수를 받고 시프트 레지스터를 이용해 **한 개의 전선으로 데이터 전송**,
> 전송 후 다시 32비트의 수를 만들고 `b` 출력

| | |
|---|---|
| 설계 대상 | PISO 송신기 + 1비트 링크 + SIPO 수신기 |
| 학습 목표 | ① 래치/플립플롭/시프트 레지스터 계보 ② 직렬화·역직렬화 ③ 완료 신호(`fin`) 설계 |

병렬 32선을 1선으로 줄이는 것이 핵심 — 배선 비용과 전송 시간의 교환.

---

## 2. 모듈 구조

| 파일 | 역할 |
|---|---|
| `src_latch/TX_shift_reg.v` | **PISO** 송신. 병렬 로드 → 1비트씩 출력, 32비트 카운터로 `fin` 생성 |
| `src_latch/RX_shift_reg.v` | **SIPO** 수신. 1비트씩 받아 32비트 복원 |
| `src_latch/Top_register.v` | TX·RX를 `N` 한 선으로 연결 |
| `tb/shift_reg_tb.v` | 테스트벤치 |
| `src_latch/SR_latch.v`, `D_latch.v`, `D_flip_flop.v` | 학습용. `.f`에 포함되지 않음 |

```
Top_register
├── reg0 : TX_shift_reg   D_in[31:0] ──load──► Q_a ──shift──► N (1비트)
│                                                    └──► fin (count==32)
└── reg1 : RX_shift_reg   N ──shift──► D_out[31:0]
                          └─── 전선 1개 ───┘
```

`.f`의 경로가 `./verilog/...`로 시작하므로 **저장소 루트에서 실행**해야 한다.

## 3. 동작 원리

### TX — 병렬 입력, 직렬 출력 (PISO)

```verilog
assign N = Q_a[0];                          // LSB부터 내보낸다

always @(posedge clk or posedge reset) begin
    if (reset)      Q_a <= 0;
    else if (load)  Q_a <= D_in;            // 병렬 로드
    else if (shift) Q_a <= {1'b0, Q_a[W-1:1]};   // 우측 시프트, 상위에 0
end
```

`{1'b0, Q_a[W-1:1]}` — 상위에 0을 채우고 한 칸 오른쪽으로 밀어낸다.
매 시프트마다 `Q_a[0]`이 새 비트가 되어 `N`으로 나간다.

우선순위: **reset > load > shift**. `if / else if` 순서가 그대로 우선순위다.

### 완료 신호

```verilog
assign fin = (count == 32) ? 1'b1 : 1'b0;

always @(posedge clk or posedge reset) begin
    if (reset)      count <= 0;
    else if (load)  count <= 0;             // 로드 시 카운터 초기화
    else if (shift) count <= count + 1;
end
```

`count`가 별도 `always` 블록에 있다. 데이터 경로와 제어 경로를 분리한 형태.
`load`에서 카운터를 0으로 되돌리므로 여러 번 전송해도 동작한다.

`count`는 `[5:0]` 6비트 — 32를 표현하려면 최소 6비트가 필요하다(0~63).

### RX — 직렬 입력, 병렬 출력 (SIPO)

```verilog
always @(posedge clk or posedge reset) begin
    if (reset)      D_out <= 0;
    else if (shift) D_out <= {N, D_out[W-1:1]};   // 상위로 밀어넣고 우측 시프트
end
```

TX가 LSB부터 보내므로, RX는 **상위에 넣고 오른쪽으로 미는** 방식으로 받아야 순서가 맞는다.

- 첫 비트(`D_in[0]`)는 32번 밀려 최종적으로 `D_out[0]`에 도착
- 마지막 비트(`D_in[31]`)는 마지막에 들어와 `D_out[31]`에 남는다

→ 32번 시프트 후 `D_out == D_in`.

### 같은 클럭 에지에 TX와 RX가 함께 동작하는 이유

TX와 RX 모두 `posedge clk`에서 동작하는데, non-blocking(`<=`)이므로
**두 블록이 모두 시프트 전 값을 읽는다.**

```
k번째 posedge:
  RX ← N (= 현재 Q_a[0], 시프트 전 값)
  TX : Q_a <= Q_a >> 1
```

RX가 옛 값을 받고 TX가 갱신되므로 비트가 하나씩 정확히 전달된다.
blocking(`=`)을 썼다면 순서에 따라 비트가 건너뛰거나 중복될 수 있다.

## 4. 핵심 코드

### 시프트 연산은 결합(concatenation)으로

```verilog
Q_a   <= {1'b0, Q_a[W-1:1]};    // 우측 시프트, 상위 0
D_out <= {N,    D_out[W-1:1]};  // 우측 시프트, 상위에 N
```

`>>` 연산자를 써도 되지만, 결합으로 쓰면 **상위에 무엇이 들어가는지 명시적**이다.
RX처럼 외부 값을 밀어넣어야 할 때는 결합이 필수다.

### 파라미터로 폭 분리

```verilog
module TX_shift_reg #(parameter W=32)( ... );
```

`W`만 바꾸면 8비트·64비트 링크가 된다.
단 `count` 폭과 `fin` 비교값(`32`)이 하드코딩되어 있어 함께 고쳐야 한다.

## 5. 검증 방법

### 자극

```verilog
clk=0; reset=1; load=0; shift=0;
#15; reset=0;
D_in = 32'hA5A5_F0F0;

@(posedge clk); load  = 1;
@(posedge clk); load  = 0; shift = 1;
wait(fin==1'b1);
@(posedge clk); shift = 0;
```

`wait(fin)`으로 32클럭을 세지 않고 완료 신호를 기다린다.
전송 길이가 바뀌어도 테스트벤치를 고칠 필요가 없는 구조.

### 결과

| 항목 | 값 |
|---|---|
| `D_in` | `a5a5f0f0` |
| `D_out` | `a5a5f0f0` |
| 일치 | **YES** |
| `fin` 상승 시각 | 335 ns |

`D_out`이 `800.. → 400.. → 200.. → 100.. → 080..` 순으로 우측 시프트되며 채워지는 것도
파형에서 확인했다. → `img_shift_register/올바른파형2.PNG`

### 입력값을 `A5A5F0F0`으로 고른 이유

처음에는 랜덤값을 썼는데 `4`가 나왔다. `4 = ...0100`은 '1' 비트가 하나뿐이라
직렬 스트림이 거의 전부 0이 되어 **비트가 제대로 이동하는지 파형으로 확인할 수 없었다.**

```
A5A5F0F0 = 1010 0101 1010 0101 1111 0000 1111 0000
```

전이가 많아 순서가 뒤집히거나 비트가 누락되면 즉시 보인다.
→ [error_log E02](error_log.md)

## 6. 배운 것 / 이후 연결

| 개념 | 이후 사용처 |
|---|---|
| **시프트 레지스터** | Project 10 FPU 배럴 시프터, LZD, FPU_Check의 in-flight 추적기 |
| **`if/else if` = 우선순위** | 해저드 유닛의 우선순위 체인 |
| **제어 경로와 데이터 경로 분리** | 카운터·상태기계를 별도 `always`로 |
| **완료 신호(`fin`)** | 다중 사이클 연산의 유효 신호 (`FPU_Valid`) |
| **직렬화 / 역직렬화** | UART, SPI 등 통신 프로토콜의 기본 |
| **관측성을 고려한 테스트 벡터** | 검증 전반 |

### 남은 개선 사항

- 테스트벤치에 자동 판정 추가 (`D_out !== D_in` 비교). 현재 콘솔 출력이 전혀 없다
- `shift=0`을 클럭 에지에서 떨어진 시점(`@(negedge clk)`)에 바꿔 레이스 제거
- `count` 폭과 `fin` 비교값을 `W`에 연동 (`count == W`)
- 여러 번 연속 전송 테스트 (`load`를 다시 assert)
- `src_latch/`의 학습용 파일(`SR_latch`, `D_latch`, `D_flip_flop`)을 별도 폴더로 분리
