## 1. 조합 논리에서 순차 논리로

## 2. 레지스터가 필요한 이유 — 신호는 동시에 도착하지 않는다

조합 논리만으로 ALU를 이어 붙이면 회로는 만들어지지만 문제가 생긴다.

경로마다 게이트 수와 배선 길이가 달라 **전파 지연이 다르다.**
따라서 두 입력이 정확히 같은 순간에 도착하지 않는다.

```
ALU0 결과 ──(빠른 경로)──┐
                          ├──► ALU2   ← 한쪽은 새 값, 한쪽은 옛 값으로 계산
ALU1 결과 ──(느린 경로)──┘
```

그 사이 ALU2의 출력은 **의미 없는 중간값**이다. 이것이 글리치.

레지스터를 사이에 두면 클럭 상승 순간의 값만 복사해 저장하므로,
요동치는 구간이 다음 단으로 전달되지 않는다.

| 효과 | 설명 |
|---|---|
| **연산 속도 차이 극복** | 경로별 지연 차이를 클럭 경계에서 흡수 |
| **데이터 안정성** | 안정된 값만 다음 단으로 |
| **오류 방지** | 글리치가 전파되지 않음 |

## 3. 래치와 플립플롭

| | 래치 (Latch) | 플립플롭 (Flip-Flop) |
|---|---|---|
| 반응 | **레벨 감지** — enable이 1인 동안 계속 통과 | **에지 감지** — 클럭 에지 순간만 |
| Verilog | `always @(*)` 에서 대입 누락 시 (의도치 않게) | `always @(posedge clk)` |
| 타이밍 분석 | 복잡 | 단순 |
| 실무 | 의도적으로는 거의 안 씀 | **동기 설계의 표준** |

**투명(transparent) 문제**: 래치는 enable이 열려 있는 동안 입력 변화가 그대로 출력으로 새어 나간다.
그래서 예측이 어렵고, 합성·타이밍 도구가 다루기 까다롭다.

Project 5에서 `cout`이 래치로 추론된 것이 의도치 않은 사례다.

### D 플립플롭

```verilog
always @(posedge clk) q <= d;
```

클럭 상승 순간의 `d`를 잡아 다음 클럭까지 유지한다. 가장 기본적인 기억 소자.

## 4. 리셋 — 비동기와 동기

```verilog
// 비동기 리셋 (이 프로젝트)
always @(posedge clk or posedge reset) begin
    if (reset) q <= 0;      // 클럭과 무관하게 즉시
    else       q <= d;
end

// 동기 리셋
always @(posedge clk) begin
    if (reset) q <= 0;      // 클럭 상승에서만
    else       q <= d;
end
```

| | 비동기 리셋 | 동기 리셋 |
|---|---|---|
| 반응 | 즉시 | 다음 클럭 에지 |
| 감지 리스트 | `or posedge reset` 포함 | 클럭만 |
| 장점 | 클럭이 없어도 초기화 가능 | 타이밍 분석 단순, 글리치 내성 |
| 단점 | 리셋 해제 타이밍(recovery/removal) 관리 필요 | 클럭이 살아있어야 함 |

`if (reset)`을 **첫 조건**으로 두는 것이 리셋 우선권이다.

### 왜 리셋이 필요한가

전원을 켠 직후 플립플롭에는 `x`(unknown)가 들어 있다.
0인지 1인지 정해지지 않은 상태로 시작하면 이후 동작을 예측할 수 없다.
리셋으로 알려진 상태(보통 0)로 정렬해야 한다.

### 테스트벤치에서 리셋 길이

```verilog
reset = 1;
#15 reset = 0;      // 클럭 한 주기(10ns)보다 길게
```

클럭 주기보다 길게 유지해 모든 플립플롭이 확실히 초기화되도록 한다.

## 5. ★ 타이밍 방정식 — 클럭 주기는 어떻게 정해지나

동기 설계의 핵심 부등식.

```
T(clk) ≥ T(cq) + T(logic) + T(setup)
```

| 항 | 이름 | 의미 |
|---|---|---|
| `T(cq)` | clock-to-Q | 클럭 에지 후 플립플롭 출력이 나오기까지 |
| `T(logic)` | 조합 논리 지연 | 두 레지스터 사이 조합 회로의 지연 |
| `T(setup)` | 셋업 타임 | 다음 클럭 에지 전에 입력이 안정되어 있어야 하는 시간 |

이 부등식이 깨지면 **셋업 위반(setup violation)** — 데이터가 제때 도착하지 못해
잘못된 값이 래치된다.

### 홀드 타임

```
T(cq) + T(logic) ≥ T(hold)
```

**홀드 타임**은 클럭 에지 **후에도** 입력이 유지되어야 하는 시간이다.
논리가 너무 빠르면 새 값이 너무 일찍 도착해 이전 값을 덮어쓴다 = **홀드 위반**.

| 위반 | 원인 | 해결 |
|---|---|---|
| **셋업 위반** | 논리가 너무 느림 | 클럭을 늦추거나 논리를 쪼갠다 (파이프라이닝) |
| **홀드 위반** | 논리가 너무 빠름 | 버퍼를 넣어 지연을 추가 |

셋업 위반은 클럭을 늦추면 해결되지만, **홀드 위반은 클럭 속도와 무관**하다.
그래서 홀드 위반이 더 까다롭다.

### 메타스테이빌리티

셋업/홀드를 위반하면 플립플롭이 0도 1도 아닌 불안정 상태에 머물 수 있다(metastability).
비동기 신호를 다른 클럭 도메인으로 넘길 때 발생하며, **동기화기(synchronizer)** 로 대응한다.

## 6. 파이프라이닝 — 모듈 사이에 레지스터를 두는 것

모듈과 모듈 사이에 레지스터를 배치하는 것을
**Registering the Outputs** 또는 **파이프라이닝(pipelining)** 이라고 한다.
고성능 칩 설계의 핵심이다.

### 왜 빨라지는가

```
파이프라인 없음:  [ALU0 → ALU1 → ALU2]  ← 세 단을 한 클럭에 다 끝내야 함
                  T(clk) ≥ T(ALU0) + T(ALU1) + T(ALU2)

파이프라인 있음:  [ALU0/ALU1] → REG → [ALU2]
                  T(clk) ≥ max(T(ALU0/1), T(ALU2))
```

**한 클럭에 끝내야 하는 논리가 짧아지므로 클럭을 높일 수 있다.**

| 효과 | 설명 |
|---|---|
| **타이밍 독립성** | 각 단이 자기 몫만 처리 → 주기가 최장 단에 의해서만 결정 |
| **신호 정화** | 앞 단의 과도 신호를 레지스터가 차단 |
| **처리량 증가** | 여러 데이터가 각 단에서 동시에 처리됨 |

### 대가

| 항목 | 내용 |
|---|---|
| **지연시간(latency)** | 결과가 나오기까지 클럭 수가 늘어난다 |
| 면적 | 레지스터 추가 |
| 복잡도 | 해저드 관리 필요 (Project 10) |

**처리량(throughput)은 늘고 지연시간(latency)은 늘어난다.** 이 구분이 중요하다.

이 프로젝트에서 출력이 입력보다 한 클럭 늦는 것이 바로 늘어난 지연시간이다.

### FPGA에서의 실제

`posedge clk`을 선언하는 순간 플립플롭이라는 장치가 새로 생기는 것이 아니다.
FPGA 안에는 이미 수만 개의 플립플롭이 배치되어 있고,
합성·배치배선 도구가 **"여기는 저장이 필요하구나"** 하고 판단해
적당한 위치의 플립플롭을 골라 연결한다.

ASIC에서는 표준 셀 라이브러리의 플립플롭 셀이 인스턴스화된다.

## 7. blocking과 non-blocking

| | `=` (blocking) | `<=` (non-blocking) |
|---|---|---|
| 실행 | 즉시, 순차적 | 우변을 모두 읽은 뒤 동시에 대입 |
| 용도 | **조합 논리** (`always @(*)`) | **순차 논리** (`always @(posedge clk)`) |

### 왜 순차 논리에 non-blocking을 쓰는가

시프트 레지스터를 예로 들면:

```verilog
// non-blocking — 올바름
always @(posedge clk) begin
    b <= a;
    c <= b;        // 이 시점의 b는 "이전" b
end
// → a→b, b→c 로 한 칸씩 이동 (플립플롭 2개)

// blocking — 틀림
always @(posedge clk) begin
    b = a;
    c = b;         // 이미 갱신된 b (= a)
end
// → c도 a가 됨 (플립플롭 1개처럼 동작)
```

non-blocking은 **모든 우변을 먼저 평가한 뒤 대입**하므로 실제 플립플롭의 동작과 일치한다.

**규칙: 순차는 `<=`, 조합은 `=`. 한 블록에서 섞지 않는다.**

## 8. 레지스터 파일

### 구조

```verilog
reg [3:0] mem[0:3];        // 4비트 × 4워드
```

4비트짜리 한 층을 4층 쌓은 배열이다.
`mem[2]`는 3번째 워드, `mem[2][1]`은 그 워드의 2번째 비트.

### 쓰기는 동기, 읽기는 조합

```verilog
always @(posedge clk) begin
    if (we) mem[add] <= din;      // 쓰기 — 클럭 에지에서만
end

assign dout = mem[add];           // 읽기 — 항상, we와 무관
```

`we=0`이어도 `dout`은 계속 값을 낸다. 읽기에는 제어가 필요 없다.

### 왜 듀얼 포트인가

CPU 명령어는 오퍼랜드를 **두 개 동시에** 필요로 한다.
```
add x3, x1, x2      ← x1과 x2를 같은 사이클에 읽어야 한다
```

읽기 포트가 하나면 두 사이클이 걸린다. 그래서 **2읽기 + 1쓰기** 포트가 표준이다.

```verilog
assign dout1 = mem[r_add1];
assign dout2 = mem[r_add2];
```

RISC-V 레지스터 파일이 정확히 이 구조다 (`rs1`, `rs2` 읽기 + `rd` 쓰기).

### 같은 주소에 동시 읽기/쓰기

한 사이클에 `mem[2]`에 쓰면서 `mem[2]`를 읽으면 어떤 값이 나오는가?

| 정책 | 결과 |
|---|---|
| **write-first** | 새로 쓴 값 (내부 포워딩) |
| **read-first** | 이전 값 |

위 코드는 `assign dout = mem[add]`가 조합이고 쓰기는 클럭 에지에 일어나므로 **read-first**다.
CPU 파이프라인에서는 이 때문에 WB 단계의 쓰기를 ID 단계의 읽기가 못 보고,
**포워딩이 필요해진다.**

## 9. 저장 계층

| 소자 | 유지 기간 | 용량 | 속도 |
|---|---|---|---|
| **플립플롭 / 레지스터** | 클럭 한 주기 (찰나) | 수십~수백 비트 | 가장 빠름 |
| **SRAM (캐시)** | 전원 있는 동안 | KB~MB | 빠름 |
| **DRAM (RAM)** | 전원 있는 동안 (주기적 리프레시) | GB | 중간 |
| **SSD / HDD** | 영구 | TB | 느림 |

레지스터가 가장 빠르고 작다. CPU가 레지스터를 32개만 두는 이유는
많이 두면 주소 비트가 늘고 접근이 느려지기 때문이다.

## 10. 비트 성장 (Bit Growth)

연산을 이어 붙이면 결과 폭이 계속 늘어난다.

```
4비트 + 4비트 = 5비트
5비트 + 5비트 = 6비트
...
```

| 방안 | 설명 | 평가 |
|---|---|---|
| **폭을 계속 확장** | 단계마다 연산기를 키운다 | 단순하지만 매번 다시 만들어야 함 |
| **다중 정밀도** | 하위/상위를 나눠 계산 (`cout`끼리 별도 연산) | 부품 재사용 가능. 로직 추가로 복잡·느려짐 |
| **Bit Growth 관리** | 중간에는 넉넉히, 출력 직전에 깎는다 | 정밀도와 면적의 균형 |
| **오버플로 허용** | 모든 폭을 통일 | 설계가 가장 단순. 정밀도 손실 |
| **Saturation (포화)** | 범위 초과 시 최댓값/최솟값으로 고정 | DSP에서 표준. 랩어라운드보다 안전 |

실무 접근은 **정밀도가 중요한 구간에서는 확장을 허용하고, 최종 단계에서 saturation으로
시스템 표준 폭에 맞추는** 방식이다.

랩어라운드(wrap-around)와 포화(saturation)의 차이:
```
8비트 부호없는, 250 + 10
  랩어라운드 → 4      (260 mod 256)
  포화       → 255    (최댓값으로 고정)
```
오디오·영상 처리에서 랩어라운드는 큰 잡음이 되므로 포화를 쓴다.

## 11. `integer`와 `genvar`

| | `integer` | `genvar` |
|---|---|---|
| 용도 | `always`/`initial` 안의 반복 (순차 실행) | `generate` 안의 반복 (하드웨어 복제) |
| 위치 | procedural 블록 | `generate` 블록 |

```verilog
integer i;
always @(posedge clk) begin
    for (i=0;i<4;i=i+1) mem[i] <= 0;     // 리셋 루프 — 순차 실행
end

genvar j;
generate
    for (j=0;j<N;j=j+1) begin : g        // 모듈 N개 복제
        adder FA( ... );
    end
endgenerate
```

레지스터 파일의 리셋 루프는 `integer`, 가산기 복제는 `genvar`다.

## 12. 용어 정리

| 용어 | 뜻 |
|---|---|
| **래치 / 플립플롭** | 레벨 감지 / 에지 감지 기억 소자 |
| **비동기 / 동기 리셋** | 클럭과 무관하게 즉시 / 클럭 에지에서만 |
| **T(cq)** | clock-to-Q. 클럭 후 출력이 나오는 시간 |
| **셋업 / 홀드 타임** | 에지 전 / 후에 입력이 안정되어야 하는 시간 |
| **셋업 위반** | 논리가 너무 느림. 클럭을 늦추면 해결 |
| **홀드 위반** | 논리가 너무 빠름. **클럭 속도와 무관** |
| **메타스테이빌리티** | 셋업/홀드 위반 시 0도 1도 아닌 불안정 상태 |
| **파이프라이닝** | 단 사이에 레지스터를 두어 클럭을 높이는 기법 |
| **latency / throughput** | 지연시간 / 처리량. 파이프라인은 전자를 늘리고 후자를 높인다 |
| **blocking / non-blocking** | `=` 즉시 대입 / `<=` 동시 대입 |
| **write-first / read-first** | 동시 접근 시 새 값 / 이전 값 |
| **saturation** | 범위 초과 시 최댓값으로 고정 (랩어라운드의 대안) |
