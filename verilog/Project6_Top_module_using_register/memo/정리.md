## 3. 동작 원리

### 왜 레지스터가 필요한가

ALU0·ALU1의 결과를 곧바로 ALU2에 꽂아도 **회로는 만들어진다.** 그런데 문제가 있다.

게이트를 통과하는 속도가 경로마다 미세하게 달라 **두 입력이 정확히 동시에 도착하지 않는다.**
그 사이 ALU2는 "한쪽은 새 값, 한쪽은 옛 값"으로 잘못 계산한다.

레지스터를 사이에 두면 클럭 상승 순간의 값만 복사해 저장하므로,
입력이 요동치는 구간이 ALU2에 전달되지 않는다.

정리하면:
- **연산 속도 차이 극복**
- **데이터 안정성**
- **오류 방지**

### 저장 계층

| 소자 | 유지 기간 |
|---|---|
| **레지스터 / 플립플롭** | 찰나 (클럭 한 주기) |
| **RAM** | 잠시 (전원 있는 동안) |
| **SSD / HDD** | 영구 |

### 리셋 우선권

```verilog
always @(posedge clk or posedge reset) begin
    if (reset) q <= 0;      // ← 먼저 검사되므로 우선권을 가진다
    else       q <= d;
end
```

`reset`을 감지 리스트에 넣고 `if`의 첫 조건으로 두면 **비동기 리셋**이 된다.
클럭과 무관하게 즉시 초기화된다.

전원을 켠 직후 레지스터에는 `x`(unknown)가 들어 있다. 리셋으로 0으로 정렬해야
이후 동작이 예측 가능해진다.

### 파이프라인 지연

출력은 입력보다 **항상 클럭 한 주기 뒤**에 나타난다. 모든 데이터가 레지스터를 거치기 때문이다.

모드가 바뀌는 순간에는 `mode`가 ALU2에 먼저 도달하고 레지스터 값은 아직 이전 것이라
**새 모드 + 옛 데이터** 조합이 잠깐 계산된다. 다음 클럭에서 정상화된다.
→ 오류가 아니다. [error_log N01](error_log.md)

## 4. 핵심 코드

### 레지스터

```verilog
module register_Nbit #(parameter N=4)(
    input clk, reset,
    input  [N:0] d,
    output reg [N:0] q
);
    always @(posedge clk or posedge reset) begin
        if (reset) q <= 0;
        else       q <= d;
    end
endmodule
```

`<=` (non-blocking)을 쓴 것이 중요하다. 순차 논리에서는 non-blocking이 원칙이다.

`[N:0]`이라 `N=4`가 **5비트**를 뜻한다. ALU 결과(캐리 포함 5비트)를 받기 위한 것이지만,
다른 모듈의 `N` 관례와 어긋난다. → [error_log R02](error_log.md)

### 레지스터 파일

```verilog
reg [3:0] mem[0:3];        // 4비트 × 4워드
```

`4비트짜리 한 층을 4층 쌓은 배열`로 이해하면 된다.

```verilog
always @(posedge clk or posedge reset) begin
    if (reset) begin
        for (i=0;i<4;i=i+1) mem[i] <= 4'b0000;
    end else if (we) begin
        mem[add] <= din;        // 쓰기는 we=1일 때만
    end
end

assign dout = mem[add];         // 읽기는 we와 무관하게 항상
```

**쓰기는 동기, 읽기는 조합**이다. `we=0`이어도 `dout`은 계속 값을 내보낸다.

### 듀얼 포트

읽기 포트가 2개면 한 사이클에 두 값을 동시에 꺼낼 수 있다.
```verilog
assign dout1 = mem[r_add1];
assign dout2 = mem[r_add2];
```

CPU가 `add x3, x1, x2` 처럼 **오퍼랜드 2개를 한 번에** 읽어야 하므로 필수 구조다.
Project 10의 `Register_file`이 이 형태다.

`dual_port_reg.v`는 현재 `else if` 위치가 잘못되어 문법 오류다.
→ [error_log E02](error_log.md)

## 5. 검증 방법

### 클럭과 리셋

```verilog
always #5 clk = ~clk;       // 5ns마다 반전 → 주기 10ns

initial begin
    clk = 0;
    reset = 1;
    #15 reset = 0;          // 클럭 한 주기보다 길게 유지
end
```

리셋을 15ns 동안 유지하는 이유는 클럭 한 주기(10ns)보다 길게 잡아
모든 레지스터가 확실히 초기화될 여유를 주기 위한 것이다.

### 자극

```verilog
#20;
for (i=0;i<4;i=i+1) begin
    mode = i;
    for (j=0;j<5;j=j+1) begin
        ALU0_a = $random % 16;
        ...
        #10;
    end
end
```

모드 4개 × 5케이스 = 20케이스. 입력은 10ns마다 갱신되고 클럭 상승은 5ns·15ns·25ns…에
있으므로, 입력이 바뀐 뒤 5ns 여유를 두고 래치된다.

### 실행 결과 (경로 오타 수정 후)

| 시각 | mode | 출력 | 비고 |
|---|---|---|---|
| 0 | xx | 0 | 리셋 상태 |
| 20000 | 00 | x | 첫 클럭 상승 전 (미확정) |
| 25000 | 00 | 17 | 클럭 상승 후 확정 |
| 35000 | 00 | 33 | |
| 70000 | 01 | 3 | 감산 모드 |

출력이 클럭 상승 시점에 갱신되는 것을 확인. 파형은 `img_top_module/파형결과.PNG`,
구조도는 `img_top_module/아키텍쳐설계.jpg`.

## 6. 비트 성장(Bit Growth) 문제

ALU0·ALU1 결과가 각 5비트(4비트 + 캐리)인데, ALU2가 그 둘을 더하면 6비트가 된다.
연산을 이어 붙일 때마다 폭이 계속 늘어난다. 선택지를 정리하면:

| 방안 | 장점 | 단점 |
|---|---|---|
| **ALU 폭을 계속 키운다** | 단순 | 단계마다 다시 만들어야 해 비효율 |
| **다중 정밀도** (`cout`끼리 따로 연산) | 기존 부품 재사용 | 연산 로직 추가, 설계 복잡, 느려짐 |
| **특정 단계에서만 확장** (Bit Growth 관리) | 정밀도와 면적의 균형 | 어디서 자를지 판단 필요 |
| **오버플로 허용** | 모든 ALU·레지스터 폭이 같아 설계가 단순 | 정밀도 손실 |

실무 접근은 **정밀도가 중요한 구간에서는 비트 확장을 허용하고, 최종 단계에서
saturation(포화) 로직으로 시스템 표준 폭에 맞추는** 방식이다.
면적 효율과 정밀도의 균형을 잡는다.
