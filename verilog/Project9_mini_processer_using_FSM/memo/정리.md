# Project 9 — 정리

[← Project 9 README](../README.md) · [Background](배경지식.md) · [Error log](error_log.md)

Project 8의 register–ALU datapath에 **IDLE/CALC/ERROR/DONE FSM**을 추가해 계산 허가와 종료·오류 상태를
관리한 프로젝트다. 정식 ISA CPU라기보다 CPU의 핵심 두 축인 **datapath + control path**를 축소해 만든
FSM-controlled arithmetic system이다.

---

## 1. 목표

- register file에서 operand 두 개를 동시에 읽는다.
- ALU가 ADD/SUB/AND/OR를 수행한다.
- FSM이 start, overflow, done 신호로 계산 상태를 제어한다.
- `N/Z/C/V` 플래그를 계산하고 overflow 시 ERROR로 전이한다.
- 정상 입력과 overflow 입력을 분리해 파형으로 검증한다.

---

## 2. 모듈 구조

```text
m_top_module
├── m_register      4-entry operand storage
├── m_ALU           operation select + flag outputs
│   ├── m_adder     ripple-carry addition
│   └── m_subtracter two's-complement subtraction
└── m_FSM           IDLE / CALC / ERROR / DONE control
```

| 파일 | 역할 |
|---|---|
| `m_top_module.v` | FSM, ALU, register 연결 |
| `m_FSM.v` | 상태 저장·전이·상태 출력·플래그 |
| `m_ALU.v` | `S_calc`와 mode에 따른 결과 선택 |
| `m_adder.v` | W단 ripple-carry adder |
| `m_subtracter.v` | `A + ~B + cin` 감산 |
| `m_register.v` | operand 저장과 dual read |
| `mini_processer1_tb.v` | 입력쌍·mode·start/done 자극 |

## 3. 동작 원리

### 상태 흐름

```text
reset
  ↓
IDLE ── start=1 ──▶ CALC
                     ├── V=1 ─────▶ ERROR ─┐
                     └── d_f=1 ───▶ DONE  ─┤ reset 전까지 유지
```

- `IDLE` — 시작 대기
- `CALC` — `S_calc=1`, ALU mode 실행
- `ERROR` — signed overflow 검출
- `DONE` — 외부 완료 입력 `d_f` 수신

CALC에서 V를 d_f보다 먼저 검사하므로 overflow와 done이 동시에 오면 ERROR가 우선한다.

---

### 데이터 흐름

```text
din ──▶ register file ──▶ a,b ──▶ adder/subtractor/logic ──▶ result
                                      │                         │
                                      └──── N/Z/C/V ────────────┘
                                                   │
                                                   ▼
                                                  FSM
```

FSM은 데이터를 직접 계산하지 않는다. datapath가 만든 `result/V`를 보고 다음 상태를 결정하고,
`S_calc`로 ALU 출력 허가를 제어한다.

---

## 4. 핵심 코드

### 상태 전이

```verilog
CALC: begin
    if (V)         next_state = ERROR;
    else if (d_f)  next_state = DONE;
    else           next_state = CALC;
end
```

조건 순서가 우선순위다. ERROR가 DONE보다 먼저다.

### ALU 기본값과 연산 선택

```verilog
always @(*) begin
    C_cout = 0;
    N_cout = 0;
    result = 0;
    if (S_error)
        result = 0;
    else if (S_calc)
        case (mode)
            2'b00: begin result=add_re; C_cout=add_c_wire; end
            2'b01: begin result=sub_re; N_cout=sub_re[3]; end
            2'b10: result=a&b;
            2'b11: result=a|b;
        endcase
end
```

기본값이 있어 mode가 바뀌어도 이전 플래그가 남지 않는다.

### overflow

```verilog
assign V = (mode==2'b00) ?
           ((a[W-1]==b[W-1]) && (result[W-1]!=a[W-1])) :
           (mode==2'b01) ?
           ((a[W-1]!=b[W-1]) && (result[W-1]!=a[W-1])) : 1'b0;
```

carry가 아니라 sign 변화 규칙으로 signed overflow를 판단한다.

## 5. 검증 방법

### 정상 경로: `a=4`, `b=1`

| mode | 연산 | 결과 |
|---|---|---:|
| `00` | ADD | 5 |
| `01` | SUB | 3 |
| `10` | AND | 0 |
| `11` | OR | 5 |

![Normal result](../img_m_processer1/결과%20a=4,b=1.PNG)

### 덧셈 overflow: `a=3`, `b=5`

`3+5=8`은 4비트 signed 범위를 넘어 V가 1이 되고 FSM이 ERROR로 이동한다.

![Addition overflow](../img_m_processer1/결과%20a=3,b=5.PNG)

### 감산 overflow: `a=2`, `b=4'hA(-6)`

덧셈 `2+(-6)=-4`는 정상이고 감산 `2-(-6)=8`에서 V가 1이 된다.

![Subtraction overflow](../img_m_processer1/결과%20a=2,b=10.PNG)

carry 단절, N 잔류, ERROR 상태를 mode 문제로 오해한 과정은 [error log](error_log.md)에 정리했다.

---

## 6. 배운 것 / 이후 연결

1. **FSM 출력은 현재 state, 전이는 현재 state+입력으로 결정된다.**
2. **현재 결과의 원인은 이전 사이클일 수 있다.** overflow가 다음 mode의 계산 허가를 끊었다.
3. **제어 경로와 데이터 경로를 분리해야 복잡도가 관리된다.**
4. **carry와 overflow는 다르다.** unsigned 범위와 signed 범위를 각각 본다.
5. **조합 출력에는 기본값이 필요하다.** 그렇지 않으면 이전 mode의 flag가 남는다.
6. **정상 케이스와 오류 유도 케이스를 분리한다.** 그래야 FSM 전이를 명확히 검증할 수 있다.

### 남은 개선 사항

- instruction memory, PC, decoder가 없어 ISA processor는 아님
- ERROR/DONE이 terminal state라 reset 없이는 다음 작업 불가
- register `mem[3]` reset 누락
- `S_error`의 ALU 연결 누락
- 일부 4비트 하드코딩과 posedge TB race
- self-checking test 없음
