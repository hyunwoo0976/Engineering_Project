# 통합테스트 01 — 정수 명령어

CPU에 실제 프로그램을 처음 올려 돌린 테스트. 정수 연산(ADD/SUB/시프트/AND) + 포워딩·해저드 경로를 한 번에 검증했다.
FPU는 다음 테스트에서.

## 목적

- port_MUX·포워딩·레지스터 파일·ALU까지 붙인 뒤, **명령어가 실제로 맞게 실행되는지** 확인
- 연산 자체 + 거리별 해저드(레지스터 파일 write-first)까지 자연스럽게 걸리도록 오퍼랜드를 앞에 몰아둠

## 검증 방법

- 레지스터 파일을 TB에서 직접 못 봐서(iverilog가 계층 배열/wire 참조를 막음) →
  `WB_Rd/WB_RegWrite/WB_OUT`을 Pipeline_CPU 출력 포트로 빼고, WB 커밋을 TB 안 **그림자 레지스터 파일**에 복사
- 끝에 `jal x0,0`(무한루프)로 상태를 얼린 뒤, 넉넉히 돌리고(≈100clk) 최종 레지스터 상태를 손계산 기대값과 비교
- 기대값은 DUT가 아니라 **ISA로 직접 계산** (독립 레퍼런스)

## 짚어둔 코너 (직접 넣은 함정)

- **거리-3 해저드**: 오퍼랜드(x4,x5)를 앞(1,2번)에 두고 5번에서 처음 소비 → `add x2`가 딱 거리-3.
  x6(거리-4)은 통과하는데 x2만 깨지는 걸로 원인을 특정 → **E24**
- **SRL vs SRA**: 시프트를 음수(x1=-4)로 돌려 부호 채움 차이 확인 (x12 = -4>>1 = -2)
- **shamt 하위 5비트**: 초기엔 srl 시프트량에 x1(=-4)을 잘못 써서 `-4 & 0x1F = 28`만큼 시프트 → 0.
  x3(=1)로 바꿔 3>>1=1 (10,11번 인코딩 수정 반영본)

## 발견한 버그

| 버그 | 증상 | 원인 | 수정 |
|---|---|---|---|
| **E24** | x2 = 2 (기대 5) | 레지스터 파일이 write-first 아님 → 거리-3에서 옛 x4 읽음 | Register_file 읽기 포트에 write-first bypass |
| **E25** | x14/15/16이 뺄셈됨 | `ALU_Control.v:55` ANDI가 `4'b0110`(SUB) | `4'b0000`(AND)로 |

상세 기록·파형은 [error_log.md](error_log.md) E24, E25.

## 결과

- **16 / 16 PASS** (x1~x16 전부 기대값 일치)
- 첫 판엔 4개(x2, x14, x15, x16) FAIL → 위 두 버그 잡고 전부 통과
