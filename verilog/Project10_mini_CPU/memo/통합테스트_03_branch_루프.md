# 통합테스트 03 — Branch + 루프 + 메모리 (ISS로 골든모델)

분기 4종 + 뒤로 뛰는 루프 + SW/LW + 포워딩을 **한 프로그램**에 다 몰아넣은 종합 테스트.
손으로는 도저히 검증이 안 돼서 **파이썬 ISS(instruction set simulator)를 golden model로** 만들어 대조했다.
이 프로그램 하나 완성하는 데 **8번쯤 고쳤고**, 매번 ISS가 내 손계산 실수를 잡아줬다.

## 목적

- **모든 분기 타입**(beq/bne/blt/bge)을 taken·not-taken 둘 다
- **뒤로 뛰는 분기 = 루프** ("두 값이 같아질 때까지 빼기")
- **SW/LW round-trip** + **포워딩/load-use**
- 분기 offset을 정밀 제어해서 원하는 실행 경로 만들기

## 검증 방법 — ISS 골든모델

레지스터를 TB에서 직접 못 봐서, WB 커밋을 그림자 레지스터에 복사해 최종 상태를 비교(테스트 01/02와 동일).
근데 이번엔 **기대값 자체를 손으로 못 구했다** — 분기 30개가 얽혀서.
그래서 파이썬으로 **RV32I 순차 시뮬레이터**를 짜서, 같은 프로그램을 돌려 정답 상태를 뽑았다.
DUT(파이프라인 CPU) vs ISS(순차 해석) → 일치하면 CPU 정상. port_MUX 때 ref_model 만든 것의 CPU 버전.

## 커버리지

- **분기 4종** beq/bne/blt/bge — **taken 다수 + not-taken 2개**(줄14, 17)
- **뒤로 뛰는 분기** (bne -8, bge -20) + **빼기 반복 루프 2바퀴** (bne -4)
- **분기 offset 정밀 제어**: 줄7 blt를 offset 12로 맞춰 줄10에 착지시킴 (안 그러면 x7 계산이 스킵됨)
- **SW/LW** round-trip (mem[4]=27 → lw로 27 회수)
- **포워딩 / load-use** 전 구간

## 8번의 수정 — ISS가 매번 잡아준 것

이 프로그램이 처음부터 이렇지 않았다. 고친 순서:
1. **x5 착각** — `x3-x2 = (x1+x2)-x2 = x1 = 9`인데 11로 봤다. 도미노로 전 분기가 어긋남
2. **x7=0** — `add x7`(줄10)이 분기에 스킵돼서 실행 안 됨. "레지스터는 쓰는 명령어가 돌아야 변한다"
3. **무한루프** — 루프 스텝이 x7=0이라 `x13 -= 0` → 영원히 안 끝남. ISS가 100만 스텝 돌고 잡음
4. **경로 안 닿음** — 줄17 bne가 taken이라 뒷부분 전부 죽은 코드
5. **offset 조정** — 줄7 blt offset 16→12로 줄10 착지, 줄17 조건 바꿔 fall-through
6~8. x16/x18 값, x7·x11 값 맞추기

**손으로 30개 분기를 정확히 추적하는 건 불가능하다.** 매번 ISS가 실행 경로를 찍어줘서 어디서 어긋났는지 보였다.

## 배운 것

- **복잡·분기 많은 프로그램엔 ISS가 필수.** 기대값을 손으로 못 구하면 검증이 성립 안 함
- **레지스터는 그걸 쓰는 명령어가 실행돼야 바뀐다** — 분기로 스킵되면 초기값 유지 (x7=0 사건)
- **무한루프는 시뮬로 잡는다** — 하드웨어 올리기 전에. 손으론 절대 못 봄
- **분기 offset으로 실행 경로를 설계**할 수 있다 (줄7을 줄10에 착지시킨 것)
- DUT vs ISS 대조 = 파이프라인 CPU의 아키텍처 정합성 검증

## 결과

- **18/18 PASS** — DUT가 ISS와 완전 일치
- 정수 통합(연산·시프트·논리·메모리·분기·루프·포워딩·load-use) **전부 검증 완료**
