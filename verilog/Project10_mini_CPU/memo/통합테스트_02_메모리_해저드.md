# 통합테스트 02 — 메모리(SW/LW) + 포워딩 + load-use

SW/LW를 검증하려고 짠 프로그램인데, 일부러 **꼬아서(torture) 넣었더니** 포워딩·store-data·load-use까지
한 번에 걸렸다. 격리 테스트 여러 개 돌릴 걸 프로그램 하나로 끝낸 셈.

## 목적

- SW/LW **round-trip**(저장 → 다시 로드) 검증
- 겸사겸사 **해저드**도 걸리게: 오퍼랜드를 바로바로 앞 결과에 의존시켜 포워딩·load-use를 유도

## 검증 방법

- 테스트 01이랑 동일: WB 커밋을 TB 그림자 레지스터에 복사 → 끝에 최종 상태를 손계산 기대값과 비교
- 메모리는 직접 못 봐서(iverilog 계층 참조 제약) **lw로 되불러와** 간접 확인 (round-trip)

## 프로그램

| # | HEX | 어셈블리 | 기대값 | 비고 |
|---|---|---|---|---|
| 1 | `00a00093` | `addi x1, x0, 10` | x1 = 10 | |
| 2 | `01400113` | `addi x2, x0, 20` | x2 = 20 | |
| 3 | `002081b3` | `add x3, x1, x2` | x3 = 30 | 10+20 · **거리-1/2 포워딩** |
| 4 | `00302023` | `sw x3, 0(x0)` | mem[0] = 30 | **store-data 포워딩**(x3 거리-1) |
| 5 | `00102223` | `sw x1, 4(x0)` | mem[4] = 10 | offset 4 = 주소 4 |
| 6 | `00002503` | `lw x10, 0(x0)` | x10 = 30 | mem[0] 되불러오기 |
| 7 | `00402583` | `lw x11, 4(x0)` | x11 = 10 | mem[4] 되불러오기 |
| 8 | `40a58633` | `sub x12, x11, x10` | x12 = -20 (`FFFFFFEC`) | **load-use**(x11) + 거리-2(x10) |
| 9 | `0000006f` | `jal x0, 0` | — | 무한루프(상태 고정) |

`offset(rs1)` = 주소는 rs1 값 + offset. 여기선 rs1=x0(0)이라 offset이 곧 주소.

## 이 프로그램이 실제로 두들긴 해저드

값을 앞 결과에 바로 의존시켜서, SW/LW만이 아니라 아래가 전부 걸렸다:

| 위치 | 해저드 | 검증한 것 |
|---|---|---|
| I3 `add x3,x1,x2` | x2 거리-1, x1 거리-2 | **포워딩** (테스트 01엔 없던 것) |
| I4 `sw x3` | x3 거리-1 (store 데이터) | **store-data 포워딩** (port_MUX E21 경로) |
| I8 `sub x12,x11,x10` | x11 = lw 바로 다음, x10 거리-2 | **load-use stall+forward** + WBtoEX |

**x12(load-use)가 제일 위험했는데 통과.** `lw x11` 결과는 MEM 끝에 나오는데 `sub`는 EX에서 필요 →
1클럭 stall + forward가 제대로 돌아야 -20이 나온다. 테스트 01에선 아예 안 걸렸던 경로라, 여기서 처음 초록불.

## 결과

- **전부 PASS**: x1=10, x2=20, x3=30, x10=30, x11=10, x12=`FFFFFFEC`(-20)
- 나머지(x4~x9, x13~x16)=0, 안 쓴 레지스터라 정상
- 버그 없음 (첫 판에 바로 통과)

## 배운 것

- **꼬아서 쏟아붓는 게 효율적이다.** SW/LW 하나 보려던 프로그램이 포워딩·store-data·load-use까지 커버.
  격리 테스트 4개 = 잘 꼰 프로그램 1개.
- 단 전제는 **정답을 알아야** 함. 여기선 의존성이 순차(체인 비슷)라 손계산이 됐다.
  더 크게/랜덤으로 갈 거면 ISS(파이썬 골든모델)가 필요하다.
- load-use가 통과한 게 핵심 — 파이프라인 stall 제어가 살아있다는 확증.
