# HDLBits 문제별 학습 기록

이 문서에 풀이 과정, 오류, 새로 배운 개념, 성공 코드를 문제별로 계속 추가한다.

## 1. 12시간 BCD 시계 — 성공

### 문제 요구사항

빠르게 도는 `clk`의 상승 에지에서 `ena=1`일 때만 시계를 1초 진행한다. `reset=1`이면 `ena`와 관계없이 `12:00:00 AM`으로 초기화한다. 이 문제의 reset은 **동기식**이다. `pm=0`은 AM, `pm=1`은 PM이다. `hh`, `mm`, `ss`는 각각 두 자리 **BCD** 값이다.

### 이 문제에서 겪은 오류

| 내가 작성하거나 관찰한 내용 | 왜 틀렸는가 | 올바른 판단 |
|---|---|---|
| `hh <= 8'd12`인데 파형의 기준 `12`와 같아 보였다 | `8'd12`의 비트 패턴은 `8'h0C`다. BCD 12의 비트 패턴 `8'h12`와 다르다 | reset 값은 `hh <= 8'h12` |
| `ss` 파형이 `9 → a → b`로 나왔다 | 일반 이진 덧셈은 `8'h09 + 1 = 8'h0A`를 만든다. BCD의 10은 `8'h10`이다 | 일의 자리 9에서 BCD 자리올림 |
| `ss == 8'd60`이면 그 자리에서 00으로 돌아갈 것이라 생각했다 | `<=`의 오른쪽과 `if`는 이번 클럭 이전 값을 읽는다. 59일 때 검사하지 않으면 60인 상태를 한 클럭 저장한다 | 현재 값 `8'h59`를 검사해 다음 값을 00으로 지정 |
| 분과 시 rollover를 독립된 `if`로 검사했다 | 분이 59인 동안 매번 시를 올릴 수 있다 | 초 59 → 00인 순간에만 분을 처리하고, 그때 분도 59면 시를 처리 |
| `11 → 12`에서 `pm <= 1`로 고정했다 | `11:59:59 PM → 12:00:00 AM`에는 1 → 0이어야 한다 | `11 → 12`에서 `pm` 반전, `12 → 1`에서는 유지 |
| `begin`과 `end`를 잘못 놓아 컴파일이 실패했다 | 한 줄짜리 `if` 뒤의 불필요한 `end`가 블록을 잘못 닫았다 | 들여쓰기와 `begin/end` 짝 확인 |

#### 파형의 `Mismatch`가 올라간 위치

처음에는 reset 후 `Yours hh=c`, `Ref hh=12`에서 올라갔다. 파형의 `c`는 `8'h0C`, `12`는 `8'h12`라 실제 비트가 다르다. `hh <= 8'h12`로 고친 뒤에는 `ss`가 `9 → a`로 바뀌는 지점에서 올라갔다. 기준은 BCD `9 → 10`이었다. 나중에 `11:59:59 PM → 12:00:00 AM`에서는 `hh/mm/ss`가 맞아도 `pm`이 1에 머물러 mismatch가 생겼다.

### 배운 개념

#### BCD와 비트 슬라이스

BCD는 십진수 한 자리를 4비트에 저장한다. `ss[7:4]`는 십의 자리, `ss[3:0]`은 일의 자리다. 예를 들어 `ss=8'h29`는 `0010_1001`이며 29초를 뜻한다.

```text
ss = 8'h29 = 0010_1001
                0010  십의 자리 2
                     1001  일의 자리 9
```

일의 자리가 9가 아니면 `ss + 1`이 맞다. 9라면 `ss + 1`은 `8'h2A`를 만들므로 다음처럼 두 자리를 따로 만든다.

```systemverilog
ss <= {ss[7:4] + 4'd1, 4'd0};  // 8'h29 → 8'h30
```

`{왼쪽, 오른쪽}`은 비트를 이어 붙이는 concatenation이다. 초가 `8'h59`라면 위 자리올림을 적용하지 않고 `8'h00`으로 돌리며 분을 올린다. 분도 같은 규칙을 사용한다. 시간은 `09 → 10`, `11 → 12`, `12 → 01`을 구별한다.

#### `ena`, reset, `<=`

`ena=0`에서 레지스터에 대입하지 않으면 값이 유지된다. `always_ff @(posedge clk)`의 플립플롭 유지 동작이며 래치가 아니다. reset은 `ena`보다 우선한다. 동기 reset이므로 `reset=1`인 **클럭 상승 에지**에서 초기화된다.

Nonblocking 대입 `<=`가 있는 블록에서는 조건문이 클럭 직전 값을 본다. 같은 실행 경로에서 동일 변수에 여러 번 `<=`를 쓰면 마지막 대입이 최종 갱신값이 된다. 아래 성공 코드의 `mm <= mm + 1'd1;`은 바로 뒤의 분 처리 대입으로 덮이는 중복 코드다. 성공 당시 코드를 보존하기 위해 원문에는 그대로 두었다.

#### AM/PM 전환

| 이전 | 다음 | `pm` |
|---|---|---|
| 11:59:59 AM | 12:00:00 PM | 0 → 1 |
| 11:59:59 PM | 12:00:00 AM | 1 → 0 |
| 12:59:59 AM | 01:00:00 AM | 유지 |
| 12:59:59 PM | 01:00:00 PM | 유지 |

### HDLBits에서 성공한 제출 코드

아래는 사용자가 성공했다고 확인한 코드 원문이다. 문법 정리나 리팩터링을 섞지 않았다.

```systemverilog
module top_module(
    input clk,
    input reset,
    input ena,
    output pm,
    output [7:0] hh,
    output [7:0] mm,
    output [7:0] ss); 
    
    always_ff @(posedge clk)begin
        if(reset)begin
            hh <= 8'h12;
            mm <= '0;
            ss <= '0;
            pm <= '0;
        end
        else begin
            if(ena)begin
                if(ss != 8'h59)begin
                    if(ss[3:0] == 4'd9)begin
                        ss <= {ss[7:4] + 4'd1, 4'd0};
                	end
                    else begin
                        ss <= ss + 8'd1;
                    end
                end
                else begin
                    ss <= '0;
                    mm <= mm + 1'd1;
                    if(mm != 8'h59)begin
                        if(mm[3:0] == 4'd9)begin
                            mm <= {mm[7:4] + 4'd1, 4'd0};
                        end
                        else begin
                            mm <= mm + 8'd1;
                        end
                    end
                    else begin
                        mm <= '0;
                        if(hh != 8'h12)begin
                            if(hh[3:0] == 4'd9)begin
                                hh <= {hh[7:4] + 4'd1, 4'd0};
                            end
                            else begin
                                hh <= hh + 1'd1;
                            end
                            if(hh == 8'h11)begin
                                if(pm == 0)begin
                                    pm <= 1'd1;
                                end
                                else begin
                                    pm <= 1'd0;
                                end
                          
                            end
                        end    
                        else begin
                            hh <= 1'd1;
                        end
                	end
                end
         
            end
        end
    end
        
           
endmodule
```

### 다음에 파형을 읽을 때

먼저 `Mismatch`가 **처음** 1이 되는 시점의 `Yours`와 `Ref`를 비교한다. 파형에 보이는 값은 글자가 아니라 신호의 비트 패턴이다. `09 → 10`, `59 → 00`, `11 → 12`, `12 → 01`, AM/PM 반전, reset 및 `ena=0` 유지 여부를 차례로 확인한다.

이 문서는 HDLBits 성공 결과와 대화 중 확인한 파형을 기록한 것이다. 문서 작성 중 별도 시뮬레이션은 실행하지 않았다.

## 2. 8×1 시프트 레지스터 LUT — 성공

### 문제를 한 문장으로

직렬 입력 `S`로 8개의 플립플롭을 채우고, 3비트 입력 `ABC`로 그중 한 비트를 선택해 `Z`에 출력한다. **쓰기 방식은 시프트, 읽기 방식은 주소 선택**이다. 사용자가 아래 코드로 케이스 통과를 확인했다.

### 입력과 출력의 역할

| 신호 | 역할 | 언제 영향을 주는가 |
|---|---|---|
| `clk` | 저장값 갱신 기준 | 상승 에지 |
| `enable` | 시프트 허가 | 상승 에지에서 1이면 이동, 0이면 유지 |
| `S` | 새로 들어오는 1비트 | 시프트 시 `Q[0]`에 저장 |
| `A`, `B`, `C` | 읽을 비트의 3비트 주소 | 조합회로인 멀티플렉서 선택 |
| `Z` | 선택된 `Q`의 값 | 주소 또는 저장값이 바뀌면 반영 |

### 저장: 왜 `S`가 `Q[0]`으로 들어가는가

문제가 방향을 명시했다. `enable=1`인 상승 에지마다 **이전 값**을 기준으로 다음처럼 갱신한다.

```text
Q[0] ← S
Q[1] ← 이전 Q[0]
Q[2] ← 이전 Q[1]
...
Q[7] ← 이전 Q[6]
```

`enable=0`이면 모든 플립플롭이 유지된다. 예를 들어 `Q=8'b0000_0000`에서 `S=1`을 한 번 넣으면 `Q[0]=1`, 다음에 `S=0`으로 한 번 더 시프트하면 그 1은 `Q[1]`로 이동한다. **MSB is shifted in first**는 원하는 8비트 내용의 최상위 비트를 먼저 `S`로 입력하라는 뜻이다. 8번 시프트 후 마지막에 넣은 비트가 `Q[0]`, 맨 처음 넣은 비트가 `Q[7]`에 남는다.

### 읽기: `ABC`는 메모리 주소

| `ABC` | 선택되는 출력 |
|---|---|
| `000` | `Z=Q[0]` |
| `001` | `Z=Q[1]` |
| `010` | `Z=Q[2]` |
| `011` | `Z=Q[3]` |
| `100` | `Z=Q[4]` |
| `101` | `Z=Q[5]` |
| `110` | `Z=Q[6]` |
| `111` | `Z=Q[7]` |

여기서는 `A`가 주소의 최상위 비트, `C`가 최하위 비트다. 예를 들어 `ABC=101`이면 이진수 주소 5이므로 `Z=Q[5]`이다. 읽기는 별도의 읽기 클럭이 없는 **조합회로**다.

### 왜 이것이 3입력 논리 함수인가

`A`, `B`, `C`의 입력 조합은 `2³=8`개다. `Q[0]`부터 `Q[7]`까지에 각 조합의 원하는 출력값을 저장하면, `ABC`가 현재 조합에 해당하는 한 비트를 고른다. 따라서 같은 회로에서 저장된 8비트를 바꾸기만 해도 다른 3입력 진리표를 구현할 수 있다. 이것이 **3입력 LUT(look-up table)**다.

### 헷갈린 지점과 수정 과정

문장에 `8×1 memory`, `shift register`, `random access`, `3-input logic function`이 한꺼번에 나온다. 각각 별도 기능으로 읽으면 된다: 8개 저장 비트, 직렬 쓰기, 주소 기반 읽기, 저장된 진리표.

처음 작성한 `Q <= {S, Q[7:1]}`은 `S`를 `Q[7]`에 넣었다. 문제는 `S`가 `Q[0]`에 들어가도록 지정하므로 `Q <= {Q[6:0], S}`로 고쳤다. **MSB is shifted in first**는 데이터의 최상위 비트를 시간상 먼저 `S`에 입력한다는 뜻이다. 먼저 들어온 비트가 계속 밀려 최종적으로 `Q[7]`에 도착한다.

처음에는 `Z` 선택용 `case`를 `always_ff` 안에 넣었다. 그러면 `Z`가 클럭 상승 에지와 `enable`에 묶여, `ABC`만 바뀌었을 때 즉시 선택값이 바뀌지 않는다. 읽기는 조합회로이므로 `assign Z = Q[{A,B,C}];`로 분리했다. `enable=0`은 저장값의 시프트만 막고, 주소에 따른 읽기는 계속 가능하다.

### HDLBits에서 성공한 제출 코드

```systemverilog
module top_module (
    input clk,
    input enable,
    input S,
    input A, B, C,
    output Z ); 
    
    reg [7:0]Q;
    always_ff @(posedge clk)begin
        if(enable)begin
            Q[7:0] <= {Q[6:0],S};
        end
    end
    
    assign Z = Q[{A,B,C}];
            

endmodule
```
