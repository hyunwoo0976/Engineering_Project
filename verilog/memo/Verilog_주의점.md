# Verilog 주의점

실제로 겪은 버그에서 뽑은 것들. 문법 교과서에는 잘 안 나오지만 반복해서 발목을 잡는 항목.

---

## 1. ★ 폭을 안 쓰면 무조건 1비트

Verilog에서 폭을 생략하면 **1비트**가 된다. 이게 가장 자주, 가장 조용히 사고를 낸다.

```verilog
wire s1_IN_A;              // ❌ 1비트! 32비트 의도였다면 값이 잘림
wire [31:0] s1_IN_A;       // ✅

output reg MEMtoEX_forward;        // ❌ 2'b10 대입 시 하위 1비트만 남아 0
output reg [1:0] MEMtoEX_forward;  // ✅

reg PASS, FAIL;            // ❌ 1비트 카운터 → 13을 못 셈
integer PASS, FAIL;        // ✅
```

**증상 패턴**
| 겉보기 | 실제 |
|---|---|
| 코드가 항상 0 또는 1만 출력 | 2비트 값이 1비트로 잘림 |
| 카운터가 `x` | 폭 문제 + 초기화 누락 |
| 결과가 전부 틀림 | 32비트 데이터가 1비트로 |

**예방**: 값을 담는 신호를 선언할 때마다 폭을 의식한다. `-Wall`을 붙이면 포트 폭 불일치는 경고로 잡힌다.

## 2. 조합 always는 맨 위에 기본값 대입

```verilog
always @(*) begin
    y = 2'b00;              // ★ 기본값
    if (a) y = 2'b01;
    else if (b) y = 2'b10;
    // else 없음
end
```

기본값이 없으면 **어느 조건도 안 걸릴 때 이전 값이 유지**된다 = **래치 추론**. 조합회로여야 하는데 기억소자가 생긴다.

**증상**: 조건을 껐는데도 출력이 이전 값을 유지한다.

`case`도 동일. `default`를 쓰거나 맨 위 기본값을 깔면 된다.

## 3. `z`와 `x`의 차이 — 디버깅 순서를 정한다

| 값 | 뜻 | 원인 |
|---|---|---|
| **`z`** | high-Z, floating | **드라이버 없음** = 포트 미연결, wire 미선언 |
| **`x`** | unknown | 미초기화, 다중 드라이버 충돌, 계산 결과가 불확정 |

> **파형에 `z`가 보이면 배선을 의심하고, `x`가 보이면 초기화/충돌을 의심한다.**

논리를 뜯기 전에 이 구분부터 하면 시간을 크게 아낀다.
실제 사례: FPU 결과가 x → 논리 버그를 찾다가 실은 인스턴스에 `.clk`/`.reset`이 미연결이었음.

`` `default_nettype none ``을 파일 맨 위에 쓰면 **선언 안 한 wire를 에러로** 잡아준다. 권장.

## 4. `if / else if` vs 독립 `if`

| 구조 | 동작 | 회로 |
|---|---|---|
| `if / else if` | 첫 번째 참만 실행 — **앞이 우선** | 우선순위 MUX |
| `if; if;` (같은 신호) | 둘 다 실행 — **뒤가 덮어씀** | 우선순위 MUX (뒤 우선) |
| `if; if;` (**다른 신호**) | 둘 다 독립 실행 | **병렬 로직** |

마지막이 중요하다. 서로 다른 신호를 다루는 판정은 **독립 if로 분리**해야 둘 다 살아난다.

실제 사례: 포워딩 유닛에서 `MEMtoEX_forward`와 `WBtoEX_forward`를 하나의 `case(1'b1)`에 넣었더니 **하나만 발화**해서 이중 포워딩이 죽었다. 두 개의 독립 if 체인으로 분리해서 해결.

## 5. `case(1'b1)`의 숨은 우선순위

```verilog
case (1'b1)
    cond_A: ...
    cond_B: ...
endcase
```

항목 조건이 **겹칠 수 있으면 위에 쓴 것이 이긴다.** `case`라고 병렬이 아니다.

**부분집합 관계인 조건은 큰 것부터 써야 한다:**
```verilog
case (1'b1)
    (fwd1 && fwd2): code = BOTH;   // ★ 가장 강한 조건 먼저
    fwd1:           code = RS1;
    fwd2:           code = RS2;
endcase
```
`fwd1`을 먼저 쓰면 both 상황에서도 `fwd1`이 걸려 **BOTH가 절대 안 나온다.**

opcode처럼 값이 서로 유일하면 우선순위 걱정이 없다.

## 6. 리팩터할 때 옛 블록을 반드시 삭제

같은 `reg`를 **두 개의 always 블록에서 대입**하면 레이스가 된다. 시뮬레이터가 순서를 보장하지 않아 결과가 들쭉날쭉해진다.

실제 사례: 새 always를 추가하고 옛것을 지우지 않아, 결과가 실행마다 바뀌는 것처럼 보였다.

**규칙: 한 신호는 딱 하나의 always에서만 대입한다.**

## 7. 신호를 추가하면 배선 체인 전체를 확인

새 제어신호 하나를 추가할 때 손대야 하는 곳:

```
디코더에서 생성
   → ID/EX 파이프 레지스터 D와 Q 양쪽 (★ 폭도 +1)
      → 상위 모듈 wire 선언
         → 하위 모듈 인스턴스 포트 연결
```

**한 군데만 빠져도 그 조건은 죽은 코드가 된다.** 컴파일은 통과하고 floating(`z`)만 남아서 조용히 동작하지 않는다.

파이프 레지스터의 **D와 Q 순서가 어긋나면** 그 뒤 신호들이 전부 밀려 스크램블 된다. 새 신호는 D/Q에서 **같은 위치**에 넣는다.

## 8. 루프 변수를 블록 밖에서 쓰지 않기

```verilog
integer x;
always @(*) begin
    if (cond1) begin
        for (x = 0; x < 7; x = x+1) ...      // 여기서 x는 0~6
    end
    else if (cond2) begin
        if (Rd[x] ...)                        // ❌ x는 이전 값(7) 또는 미초기화
    end
end
```

`x`는 모듈 레벨 변수라 값이 남는다. 배열 범위를 넘어 접근하면 결과가 조용히 `x`가 된다.
→ 각 분기가 **자기 루프를 가져야** 한다.

## 9. 파이프라인 레지스터의 stall / flush

```verilog
if (reset || flush)  Q <= 0;      // flush 우선
else if (!stall)     Q <= D;      // stall=1이면 홀드
```

| 신호 | 1일 때 |
|---|---|
| `stall` | **홀드** (D를 안 받음) |
| `flush` | **클리어** (버블 삽입) |

**load-use 해저드에서 둘을 혼동하면 데드락이 난다.**
- `IF_ID_stall` → 소비자를 ID에 붙잡음 (한 번 더 돌게)
- `ID_EX_flush` → EX에 버블 삽입 (**생산자는 MEM으로 보내야 하므로 stall이 아니라 flush**)

`ID_EX_stall`을 쓰면 생산자가 EX에 갇혀 데이터가 영영 안 나오고, 조건이 영구히 유지되어 멈춘다.

> **stall 조건을 추가할 때마다 "이건 어떻게 해제되나"를 먼저 확인한다.**

## 10. 상수 표기법

**`<비트폭>'<진법><값>`** — 앞의 숫자는 **자릿수가 아니라 비트 폭**이다.

| 표기 | 비트 | 값 |
|---|---|---|
| `5'h7` | 5 | 7 (`00111`) |
| `5'b00111` | 5 | 7 (같음) |
| `5'd7` | 5 | 7 (같음) |
| `8'hFF` | 8 | 255 |
| `4'd10` | 4 | 10 (`1010`) |

- **hex 한 자리 = 정확히 4비트**, 표현 범위는 **0~15** (16까지가 아님)
- 폭보다 큰 값은 **상위가 잘린다**: `5'h3F`(63) → `5'b11111`(31)
- `% N` 은 `0 ~ (N-1)`

## 11. 두 레지스터 파일을 쓸 때 (FPU 있는 설계)

정수 레지스터와 FP 레지스터는 **같은 5비트 주소 공간을 공유**한다. `x5`와 `f5`는 번호만 같고 완전히 다른 레지스터다.

**번호만 비교하면 가짜 매치가 생긴다.** 해저드·포워딩 판정에는 파일 구분이 필요하다:
- 생산자 쪽: `RegWrite`(정수) vs `FRegWrite`(FP)
- 소비자 쪽: `uses_Rs*`(정수) vs `uses_FRs*`(FP)
- **같은 파일 + 같은 번호**일 때만 진짜 매치

또한 **`x0`는 항상 0이므로 포워딩 금지**지만, **`f0`는 일반 레지스터**라 포워딩해야 한다.
→ `Rd != 0` 게이팅을 **정수 항에만** 붙인다.

## 12. 소비자 판정은 "쓰는가"가 아니라 "읽는가"

포워딩·해저드에서 소비자를 `RegWrite`로 구분하면 **분기(branch)를 놓친다.** 분기는 `RegWrite=0`인데 `rs1`, `rs2`를 읽는다.

명령어별로 어느 소스를 읽는지 신호로 만들어 두면(`uses_Rs1`, `uses_Rs2`) 명령어 타입별 분기가 사라진다:

| 명령어 | rs1 | rs2 |
|---|---|---|
| R-type / SW / Branch | O | O |
| addi / LW / JALR | O | X |
| **JAL** | **X** | **X** |

`JAL`이 둘 다 X인 게 포인트 — 레지스터를 안 읽으므로(pc+imm) 포워딩 대상이 아니다.

## 13. timescale

```verilog
`timescale 1ns/1ps      // <시간단위>/<정밀도>
```

- 앞(1ns) — `#1`이 1ns
- 뒤(1ps) — 1ps까지 표현 가능 (`#0.5` = 500ps)

**모듈에 없으면** 다른 파일에서 상속받거나, 파형 시간축이 `sec`로 보인다. 파일마다 선언하는 습관을 권한다.

## 14. 설계 사고법 — 케이스를 나열하지 말고 불변식을 찾기

조건이 3개 이상 나열되기 시작하면 멈추고 물어본다:

> **"이 케이스들이 공통으로 답하려는 질문이 뭐지?"**

포워딩 유닛의 경우 그 질문은 **"이 오퍼랜드는 어디서 오나?"** 하나였다.
명령어별로 나열하면 12가지, 26가지로 폭발하고 반드시 누락이 생긴다.
오퍼랜드 단위로 보면 wire 4개로 끝난다.

**명령어 이름이 조건식에 등장하면 추상화가 덜 된 신호다.**
