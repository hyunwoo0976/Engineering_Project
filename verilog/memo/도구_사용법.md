# 시뮬레이션 도구 사용법

Icarus Verilog + GTKWave 환경. 프로젝트 공통.

---

## 1. 기본 흐름

**컴파일 → 실행 → 파형 확인** 3단계.

```bash
iverilog -g2012 -Wall -s <최상위모듈> -o sim.out -f <파일목록>.f
```

```bash
vvp sim.out
```

```bash
gtkwave dump.vcd
```

---

## 2. iverilog 옵션

| 옵션 | 뜻 | 비고 |
|---|---|---|
| `-o <파일>` | 출력 실행파일 이름 | 없으면 `a.out` |
| `-s <모듈>` | 최상위 모듈 지정 | TB가 여러 개일 때 **필수** |
| `-f <파일>` / `-c <파일>` | 소스 목록 파일 | **둘은 완전히 같음** (동의어) |
| `-g2005` | Verilog-2005 | **기본값** |
| `-g2012` | SystemVerilog 기능 포함 | 인자 없는 function 등에 필요 |
| `-Wall` | 모든 경고 표시 | **습관적으로 붙일 것** |
| `-I <경로>` | include 경로 | |
| `-D <매크로>` | 매크로 정의 | |

### `-s`가 필요한 이유
파일 목록에 테스트벤치가 여러 개 있으면, iverilog가 "아무도 인스턴스화하지 않은 모듈"을 모두 최상위로 잡아서 **전부 동시에 실행**된다. `-s`로 하나만 지정한다.

### `-g2012`가 필요한 경우
- **인자 없는 function** — 순수 Verilog는 function에 input이 최소 1개 있어야 함
  ```
  -g2005: error: Function ref_model has no ports.
  ```
- `logic`, `always_comb`, `always_ff`, class 등 SystemVerilog 문법
- 앞으로 SystemVerilog로 넘어갈 것이므로 **처음부터 붙이는 습관**을 권함

## 3. 파일 목록(`.f`) 사용

한 줄에 한 파일. 주석은 `//`.

```
//========== ALU ==========
./verilog/ProjectN/src/ALU.v
./verilog/ProjectN/src/ALU_Control.v
//========== TB ==========
./verilog/ProjectN/tb/ALU_tb.v
```

### 경로 기준이 "실행 디렉토리"임에 주의
`./verilog/...` 처럼 상대경로로 쓰면 **프로젝트 루트에서 실행**해야 한다.
다른 폴더에서 돌리면 파일을 못 찾는다.

### 자주 나는 실수
| 증상 | 원인 |
|---|---|
| `No such file or directory` | 파일을 옮겼는데 `.f`를 안 고침 |
| `Unknown module type: X` | 모듈 파일이 목록에 없음 |
| 대소문자 오류 (Linux에서만) | `Top_module` vs `TOP_module`. Windows는 통과, Linux/CI는 실패 |

## 4. 출력 파일이 생기는 위치

**소스 파일 옆이 아니라, 명령을 실행한 디렉토리**에 생긴다.

| 파일 | 위치 결정 |
|---|---|
| `sim.out` | `-o` 옵션 + 현재 디렉토리 |
| `*.vcd` | `$dumpfile()` 경로 + **vvp 실행 디렉토리** |

`$dumpfile("out.vcd")` 처럼 파일명만 쓰면 루트에 생긴다. 특정 폴더에 두려면 경로를 넣는다.

## 5. ★ 컴파일 실패 시 함정

**컴파일이 실패하면 이전 `sim.out`이 그대로 남는다.** 그 상태로 `vvp sim.out`을 실행하면 **예전 코드가 돌아간다.** 코드를 고쳤는데 결과가 안 바뀌어 한참 헤매게 된다.

해결: 컴파일 성공 여부를 확인한 뒤 실행.

PowerShell (Windows PowerShell 5.1은 `&&`가 안 됨):
```bash
iverilog -g2012 -Wall -s Testbench -o test.out -f ./filelist.f; if ($?) { vvp test.out }
```

## 6. 파형 덤프

```verilog
initial begin
    $dumpfile("test.vcd");
    $dumpvars(0, Testbench);
end
```

`$dumpvars(레벨, 스코프)` — 숫자는 **몇 계층 아래까지** 덤프할지.

| 값 | 의미 |
|---|---|
| `0` | 그 스코프 아래 **전부** (무제한) |
| `1` | 지정 모듈의 **자기 신호만** (하위 모듈 내부는 안 보임) |
| `2` | 자기 + 한 계층 아래 |

내부 신호를 디버깅하려면 `0`. 큰 설계에서 VCD가 너무 커지면 서브모듈만 지정한다:
```verilog
$dumpvars(0, Testbench.u_dut.u_FADD_core);
```

## 7. 자주 만나는 경고와 의미

| 경고 | 의미 | 조치 |
|---|---|---|
| `implicit definition of wire 'X'` | 선언 없이 wire를 씀 (자동 1비트 생성) | `wire X;` 명시. `` `default_nettype none ``으로 예방 |
| `dangling input port N (X) floating` | 인스턴스에서 입력 포트 미연결 | 연결. **결과가 `z`가 되어 조용히 오동작** |
| `Port N (X) expects N bits, got M` | 폭 불일치 (자동 패딩/절단) | 폭 맞추기 |
| `timescale for X inherited from another file` | 그 모듈에 `` `timescale ``이 없음 | 각 파일에 선언 |
| `Some modules have no timescale` | 위와 동일 | 파형 시간축이 `sec`로 보이는 원인 |
| `@* is sensitive to all N words in array` | 배열 전체가 감도 리스트에 포함 | 의도적이면 무해 |

**`-Wall`을 안 붙이면 이 경고들이 안 보인다.** 폭 불일치·미연결은 조용히 오동작하는 유형이라, 경고가 유일한 단서인 경우가 많다.

## 8. GTKWave 팁

| 동작 | 방법 |
|---|---|
| 신호 추가 | 좌측 트리에서 선택 후 `Append` |
| 값 표기 진법 변경 | 신호 우클릭 → `Data Format` → Hex/Decimal/Binary |
| 시간 확대/축소 | `Zoom Fit`으로 전체 보기 시작 |
| 신호 그룹 저장 | `File → Write Save File` (`.gtkw`) → 다음에 재사용 |

**색으로 상태 읽기**
- **초록** — 정상 (0/1)
- **빨강** — `x` (충돌 또는 미초기화)
- **파랑/회색** — `z` (미연결, floating)

> `z`가 보이면 **배선 문제**, `x`가 보이면 **초기화/충돌 문제**. 논리를 뜯기 전에 먼저 연결을 확인한다.

## 9. 실전 명령 예시

Project10 전체 CPU:
```bash
iverilog -g2012 -Wall -s Pipeline_CPU_tb -o CPU.out -f ./verilog/Project10_mini_CPU/F_file/CPU.f
```

특정 유닛만:
```bash
iverilog -g2012 -Wall -s Testbench -o test.out -f ./verilog/Project10_mini_CPU/F_file/F_file.f
```

출력이 많을 때 실패만 보기:
```bash
vvp test.out | grep FAIL
```

파일로 저장:
```bash
vvp test.out > result.txt
```
