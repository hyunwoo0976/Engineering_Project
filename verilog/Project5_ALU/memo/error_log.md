## E01 · `sum`이 `zzzz`로 나옴

- **[파형]** `img_ALU/error.PNG`

- **[증상]** 결과가 전부 `z`. 파형에서 `cin`과 `sub_cout`이 아무 변화도 보이지 않는다.

- **[원인]** **High-Impedance 상태.** 전선이 어디에도 연결되지 않아 공중에 떠 있는 상태.
  출력을 구동하는 드라이버가 없으면 `wire`는 `z`가 된다.

- **[수정]** 미연결 포트를 연결

- **[확인]** 현재 `alu_Nbit.v`에서 `add_cout`, `sub_cout`이 각 하위 모듈의 `.cout`에
  정상 연결되어 있고, 시뮬레이션에서 `z`가 나오지 않는다.

- **[메모]** `z`는 `x`와 다르다. `x`는 값 충돌이나 미초기화, **`z`는 드라이버 없음**.
  파형에서 `z`가 보이면 논리를 뜯기 전에 **배선부터** 확인하는 것이 빠르다.

## E02 · AND는 항상 0, OR는 항상 1

- **[증상]** `a`를 0→15, `b`를 15→0으로 넣었을 때
  - `mode=10` (AND) 결과가 **항상 `0000`**
  - `mode=11` (OR) 결과가 **항상 `1111`**

- **[원인]** 4비트에서 `b = 15 - a` 는 `~a` 와 같다.
  ```
  a = 0101 (5)  →  b = 15-5 = 10 = 1010 = ~0101
  ```
  따라서
  ```
  a & ~a = 0000   (항상)
  a | ~a = 1111   (항상)
  ```
  입력 16가지가 서로 다르지만 논리 연산 결과는 한 가지로 고정된다.
  AND/OR 게이트가 잘못 배선되어 있어도 이 패턴으로는 드러나지 않는다.

- **[수정]** 테스트벤치 자극을 **`$random`으로 교체**
  ```verilog
  for (i=0; i<4; i=i+1) begin
      mode = i;
      for (j=0; j<10; j=j+1) begin
          x = $random;
          y = $random;
          cin = 1'b0;
          #10;
      end
  end
  ```

- **[확인]** 랜덤 입력에서 AND/OR 결과가 케이스마다 달라진다.
  ```
  mode=10 | a=1011, b=0101 | 결과=00001
  mode=10 | a=1101, b=1111 | 결과=01101
  mode=11 | a=1100, b=1010 | 결과=01110
  ```

- **[메모]** Project 4의 테스트벤치도 `y = 15 - x` 를 쓰고 있어 같은 문제가 있다
  (거기서는 캐리 전파가 한 번도 발생하지 않음). → `Project4_N_bit_Adder/memo/error_log.md` R01

## 재검토에서 확인한 사항

### R01 · `cout`이 mode 10/11에서 래치로 남는다

- **[증상]** `mode=10`(AND), `mode=11`(OR) 케이스 20개 전부 `cout = 1`로 고정.
  입력이 바뀌어도 변하지 않는다.
  ```
  mode=10 | a=1011, b=0101 | ... cout=1
  mode=10 | a=0001, b=1000 | ... cout=1     ← 결과가 0인데도 cout=1
  mode=11 | a=1111, b=1111 | ... cout=1
  ```

- **[원인]** `alu_Nbit.v:29~43` — `always @(*)` 안의 `case`에서
  **mode 10, 11 분기가 `cout`에 대입하지 않는다.**
  ```verilog
  2'b00: begin result = {add_cout, add_sum}; cout = add_cout; end
  2'b01: begin result = {1'b0, sub_sum};     cout = sub_cout; end
  2'b10: result = {1'b0, a & b};    // cout 미대입
  2'b11: result = {1'b0, a | b};    // cout 미대입
  ```
  조합 `always`에서 어떤 경로가 신호를 대입하지 않으면 **이전 값이 유지**된다 = 래치 추론.
  직전 mode 01의 마지막 `sub_cout`(=1)이 mode 10·11 내내 그대로 남았다.

- **[영향]** AND/OR 연산에는 캐리가 없으므로 `cout`은 0이어야 한다.
  현재는 이전 연산의 잔여 값을 내보내고 있다.

- **[조치안]** `always` 맨 위에 기본값을 깔거나 각 분기에서 `cout = 0`을 명시
  ```verilog
  always @(*) begin
      result = 0;
      cout   = 0;          // 기본값
      case (mode)
          ...
      endcase
  end
  ```

- **[미수정]** 아직 그대로 둠

### R03 · 자동 판정이 없음

`$random`으로 40케이스를 돌리지만 기대값과 비교하지 않는다.
mode별 기대값을 Verilog 연산으로 만들 수 있어 자동화 비용이 낮다.

```verilog
case (mode)
    2'b00: exp = x + y + cin;
    2'b01: exp = (x >= y) ? x - y : y - x;
    2'b10: exp = x & y;
    2'b11: exp = x | y;
endcase
if (result[3:0] !== exp[3:0]) $display("[FAIL] mode=%b x=%b y=%b", mode, x, y);
```

## 교훈

1. **`z`는 배선, `x`는 초기화/충돌.** 파형에서 어느 쪽인지 먼저 구분하면 원인 탐색이 빨라진다 (E01)
2. **입력이 다양해 보여도 결과가 고정이면 검증되지 않은 것이다.** `b = 15 - a`는 `~a`라
   논리 연산이 상수로 굳는다. 랜덤 자극으로 바꿔 해결했다 (E02)
3. **조합 `always`의 모든 경로에서 모든 출력에 대입한다.** 안 하면 래치가 생긴다 (R01)
4. **같은 모듈을 두 곳에 두지 않는다.** 컴파일이 통과해도 어느 것이 쓰이는지 불확실해진다 (R02)
