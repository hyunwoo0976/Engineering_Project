## 3. 동작 원리

### 연산 선택

```verilog
always @(*) begin
    case (mode)
        2'b00: begin result = {add_cout, add_sum}; cout = add_cout; end   // 덧셈
        2'b01: begin result = {1'b0, sub_sum};     cout = sub_cout; end   // 감산
        2'b10: result = {1'b0, a & b};                                    // AND
        2'b11: result = {1'b0, a | b};                                    // OR
        default: result = 0;
    endcase
end
```

가산기와 감산기는 **항상 동시에 계산**되고 있다. `case`는 그중 어느 결과를 내보낼지만 고른다.
즉 `case` 문이 합성되면 **4:1 MUX**가 된다.

> 하드웨어는 소프트웨어처럼 "필요한 것만 실행"하지 않는다.
> 두 연산기 모두 게이트로 존재하며 전력을 쓴다. 대신 선택은 즉시 이루어진다.

### 결과 비트폭

`result`가 `[N:0]` = **5비트**다.

| mode | `result[4]` | 의미 |
|---|---|---|
| `00` 덧셈 | `add_cout` | 4비트+4비트 = 최대 5비트 |
| `01` 감산 | `1'b0` | 항상 양수(`|a−b|`)라 5번째 비트 불필요 |
| `10` AND | `1'b0` | 논리 연산은 4비트 |
| `11` OR | `1'b0` | 같음 |

덧셈에서만 5번째 비트가 의미를 갖는다. 그런데 `cout`도 따로 출력하므로
mode 00에서 `result[4]`와 `cout`이 같은 값 — 중복이다.

비트폭을 어떻게 둘지 고민한 기록은 [error_log 설계 판단](error_log.md) 참고.

## 4. 핵심 코드

### 하위 모듈은 파라미터를 전달

```verilog
N_bit_adder   #(.N(N)) uut0( ... );
calculate_sub #(.N(N)) uut1( ... );
```

최상위의 `N`이 하위로 전달되어 폭이 일관되게 유지된다.

### AND/OR는 하위 모듈 없이 직접

```verilog
2'b10: result = {1'b0, a & b};
2'b11: result = {1'b0, a | b};
```

비트 단위 논리 연산은 게이트 N개면 되므로 별도 모듈을 만들지 않았다.
`{1'b0, ...}`로 5비트에 맞춰 상위를 0으로 채운다.

## 5. 검증 방법

### 랜덤 자극을 처음 사용

```verilog
for (i=0; i<4; i=i+1) begin
    mode = i;
    for (j=0; j<10; j=j+1) begin
        x = $random;
        y = $random;
        cin = 1'b0;
        #10;
    end
end
```

mode별 10케이스 × 4모드 = **40케이스**.

처음에는 `a`를 0→15, `b`를 15→0으로 넣었는데 **AND가 항상 0, OR가 항상 1**로 나왔다.
`b = 15 - a`가 4비트에서 `~a`와 같아 논리 연산 결과가 상수로 굳은 것.
그래서 `$random`으로 교체했다. → [error_log E02](error_log.md)

`$random`은 32비트를 반환하지만 `reg [3:0]`에 대입하면 하위 4비트만 남아 0~15가 된다.

### 실행 결과 예

| mode | a | b | result | cout |
|---|---|---|---|---|
| 00 | 0100 | 0001 | 00101 (5) | 0 |
| 00 | 1101 | 1101 | 11010 (26) | 1 |
| 01 | 0010 | 1111 | 01101 (13) | 1 |
| 10 | 1011 | 0101 | 00001 | — |
| 11 | 1100 | 1010 | 01110 | — |

덧셈·감산·논리 연산 모두 정상. 실행 화면은 `img_ALU/ALU_wave.PNG`.

### 확인된 문제

- `mode` 10·11에서 **`cout`이 이전 값에 고정**된다 (래치) → [error_log R01](error_log.md)
- `$monitor`의 라벨과 인자가 어긋나 있다 → [error_log R03](error_log.md)
- 자동 판정이 없어 40케이스를 눈으로 확인해야 한다

## 6. 배운 것 / 이후 연결

| 개념 | 이후 사용처 |
|---|---|
| **`case`로 연산 선택 = MUX** | Project 10 ALU_Control, FPU op 선택 |
| **하위 모듈 통합** | CPU 데이터패스 전체 구성 |
| **조합 `always`의 완전성** | 래치 방지. Project 10에서 반복 등장 |
| **`$random` 자극** | Project 10의 제약 랜덤 검증으로 발전 |
| **결과 비트폭 설계** | 캐리·오버플로를 별도 플래그로 분리하는 판단 |

### 남은 개선 사항

- `always` 맨 위에 `result = 0; cout = 0;` 기본값을 깔아 래치 제거
- `result`를 `[N-1:0]`로 줄여 `cout`과의 중복 정리
- 로컬 `subtractor.v` 또는 Project 3 참조 중 하나만 남기기
- `$monitor` 라벨 수정 (`sum=` → `result=`, `result=` → `cout=`)
- 자동 판정 추가 — mode별 기대값을 Verilog 연산으로 만들 수 있다
- 플래그 확장: Zero, Negative, Overflow (현재는 `cout`만)
