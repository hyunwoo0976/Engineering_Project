# Project 8 — 정리

[← Project 8 README](../README.md) · [Background](배경지식.md) · [Error log](error_log.md)

Project 5의 ALU와 dual-port register file을 MUX로 연결해, 외부 입력과 연산 결과를 다시 저장할 수 있는
작은 **register–ALU feedback datapath**를 만든 프로젝트다.

---

## 1. 목표

- 네 칸 register file에 주소를 지정해 값을 저장한다.
- 두 read port로 ALU operand 두 개를 동시에 공급한다.
- mode에 따라 ADD/SUB/AND/OR를 실행한다.
- 외부 테스트 값과 ALU 결과 중 하나를 MUX로 선택해 다시 register file에 쓴다.
- 파형으로 저장 → 읽기 → 연산 → 피드백의 전체 경로를 검증한다.

---

## 2. 모듈 구조

```text
Top_system
├── dual_port_reg   4-entry storage, 1 write + 2 read ports
├── alu_Nbit        ADD / SUB / AND / OR
└── MUX             external TB_v or ALU feedback
```

| 파일 | 역할 |
|---|---|
| `src_Register2/Top_system.v` | 세 블록 연결과 내부 wire 정의 |
| `src_Register2/dual_port_reg.v` | 동기 write, 비동기 dual read |
| `src_Register2/MUX.v` | `count`로 입력원 선택 |
| `tb/Top_system_tb.v` | register 초기값과 mode 4종 자극 |
| `Top_system.f` | Project 2~5 재사용 모듈을 포함한 컴파일 목록 |

## 3. 동작 원리

### 1) reset

register 네 칸을 0으로 초기화한다.

### 2) 외부 값 저장

`count=0`이면 MUX가 `{1'b0, TB_v}`를 선택한다. 테스트에서는 주소 0에 4, 주소 1에 1을 저장한다.

### 3) operand 읽기

`r_add1=0`, `r_add2=1`로 두 register를 동시에 읽어 ALU의 A/B 입력에 연결한다.

### 4) 연산

`mode=00/01/10/11` 순서로 ADD/SUB/AND/OR를 선택한다.

### 5) 결과 피드백

`count=1`이면 MUX가 `alu_v`를 선택하고, `we=1`인 상승 에지에 선택한 write address로 결과를 저장한다.

---

## 4. 핵심 코드

```verilog
dual_port_reg u_reg(
    .din(MUX_reg),
    .r_add1(r_add1), .r_add2(r_add2),
    .dout1(dout1_a), .dout2(dout2_b)
);

alu_Nbit u_alu(
    .a(dout1_a), .b(dout2_b),
    .mode(mode), .result(alu_v)
);

MUX u_mux(
    .count(count), .alu_v(alu_v),
    .TB_v(TB_v), .din(MUX_reg)
);
```

세 모듈의 개별 기능보다 중요한 것은 연결 방향이다. register 출력이 ALU로 가고, ALU 출력은 MUX를
거쳐 다시 register 입력으로 돌아온다. 이 고리가 Project 10의 write-back datapath의 축소판이다.

---

## 5. 검증 방법

초기 operand는 A=4, B=1이다.

| mode | 연산 | 기대값 | 파형 |
|---|---|---:|---:|
| `00` | ADD | 5 | 5 |
| `01` | SUB | 3 | 3 |
| `10` | AND | 0 | 0 |
| `11` | OR | 5 | 5 |

![Project 8 final waveform](../img_top%20system/최종파형.PNG)

오류 파형에서는 write 자극 시점과 read address를 잘못 해석해 register 값이 뒤섞인 것처럼 보였다.
원인과 파형 비교는 [error log E01~E02](error_log.md)에 정리했다.

---

## 6. 배운 것 / 이후 연결

1. **통합에서 새 버그가 생긴다.** 개별 register와 ALU가 맞아도 주소·MUX·타이밍 연결이 틀릴 수 있다.
2. **두 read port는 주소가 독립이다.** 같은 주소를 주면 같은 값이 나오는 것이 정상이다.
3. **클럭 에지는 값을 넣는 시간이 아니라 DUT가 받는 시간이다.** TB 자극은 에지 전에 준비한다.
4. **데이터패스는 고리로도 연결된다.** ALU 결과를 다시 저장하면서 여러 단계 계산이 가능해진다.
5. **제어 경로가 필요해진다.** `we/count/mode/address`를 사람이 순서대로 바꾸는 한계를 Project 9 FSM이 해결한다.

### 남은 개선 사항

- register 0·1과 단일 operand 조합만 검증
- 파형 육안 확인이며 self-checking assertion 없음
- N비트 데이터와 N+1비트 carry 포함 데이터의 폭 규칙이 혼재
- TB가 일부 제어를 posedge에 바꿔 race 가능성 존재
