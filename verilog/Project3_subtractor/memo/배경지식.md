---

## 1. 음수를 표현하는 세 가지 방식

N비트로 음수를 나타내는 방법은 역사적으로 셋이 있었다.

### ① 부호-크기 (Sign-Magnitude)

MSB를 부호, 나머지를 크기로 쓴다. 4비트 예: `1101` = −5

| 장점 | 단점 |
|---|---|
| 사람이 읽기 쉽다 | **+0(`0000`)과 −0(`1000`)이 따로 존재** |
| | 덧셈 회로가 복잡 (부호를 보고 더할지 뺄지 분기) |

IEEE-754 부동소수점의 **부호 비트가 이 방식**이다. 그래서 FPU에서 `+0.0`과 `−0.0`이 구분되고,
덧셈 전에 부호를 비교해 실제 연산이 덧셈인지 뺄셈인지(`eff_sub`) 판단하는 단계가 필요하다.

### ② 1의 보수 (One's Complement)

모든 비트를 반전. 4비트 예: `−5` = `~0101` = `1010`

| 장점 | 단점 |
|---|---|
| 반전만 하면 됨 (게이트가 적다) | **+0(`0000`)과 −0(`1111`)이 여전히 둘** |
| | 덧셈 후 **end-around carry**(최종 캐리를 LSB에 다시 더하기)가 필요 |

### ③ 2의 보수 (Two's Complement) — 현대 표준

반전 후 1을 더한다. 4비트 예: `−5` = `~0101 + 1` = `1011`

| 장점 |
|---|
| **0이 하나** (`0000`뿐) |
| **덧셈 회로 하나로 가감산 모두 처리** |
| 표현 범위가 한 개 더 넓다 (−8 ~ +7) |

정수 연산은 사실상 전부 2의 보수를 쓴다. RISC-V, ARM, x86 모두 그렇다.

## 2. 왜 `~b + 1`이 −b인가

N비트에서 2의 보수의 정의:

```
−b ≡ 2^N − b   (mod 2^N)
```

그리고 `~b`는 각 비트를 반전한 것이므로

```
~b = (2^N − 1) − b        ← 모든 비트가 1인 값에서 b를 뺀 것
~b + 1 = 2^N − b = −b
```

즉 `~b + 1`은 정의를 그대로 계산한 것이다.

### 4비트 확인

| b | ~b | ~b+1 | 해석 |
|---|---|---|---|
| `0001` (1) | `1110` | `1111` | −1 |
| `0101` (5) | `1010` | `1011` | −5 |
| `1000` (8) | `0111` | `1000` | −8 (자기 자신) |
| `0000` (0) | `1111` | `0000` | 0 (캐리 버림) |

`1000`(−8)은 보수를 취해도 자기 자신이다. 4비트에서 +8을 표현할 수 없기 때문이며,
2의 보수의 범위가 비대칭(−2^(N-1) ~ +2^(N-1)−1)인 이유다.

`0`의 보수는 `10000`이 되지만 4비트를 넘는 캐리를 버려 `0000` — 0이 하나로 유지된다.

## 3. 감산을 덧셈 회로로 처리하는 이유

```
a − b = a + (~b + 1)
```

이 등식 덕분에 **가산기 하나로 덧셈과 뺄셈을 모두 처리**할 수 있다.

```
        ┌─────────┐
a ──────┤         │
        │  ADDER  │──→ result
b ──►[~]┤         │
   sub  └────┬────┘
             │ cin = sub
```

- `sub = 0` → `b`를 그대로, `cin = 0` → **덧셈**
- `sub = 1` → `~b`, `cin = 1` → **뺄셈**

`b`의 각 비트를 `b ^ sub`로 통과시키면 XOR 게이트 N개로 조건부 반전이 된다.
`+1`은 별도 가산기 없이 `cin`에 태운다. → **면적이 거의 늘지 않는다.**

Project 5의 ALU가 이 방식으로 add/sub를 통합한다. Project 10의 FPU에서도
`Cond_Inverter`가 `eff_sub`에 따라 가수를 조건부 반전하고 `Cin`에 태우는 같은 구조를 쓴다.

### 이 프로젝트가 택한 방식과의 차이

이 프로젝트는 `sub` 신호 없이 **항상 뺄셈**이고, 대신 크기를 비교해 순서를 바꾼다.

```verilog
val_a = (a>=b) ? a : b;    // 큰 값
pre_b = (a>=b) ? b : a;    // 작은 값
```

결과가 음수가 되지 않으므로 부호 처리가 불필요해진다. 대신 **비교기(comparator)와 MUX 2개**가 추가된다.
크기 비교는 내부적으로 또 하나의 감산이므로 하드웨어 비용이 작지 않다.

부호 있는 결과가 필요하면 비교를 없애고 2의 보수 결과를 그대로 쓰면서 MSB를 부호로 해석하는 편이 싸다.

## 4. borrow와 carry — 감산에서 cout의 의미

2의 보수 감산에서 최종 캐리는 **빌림(borrow)의 반대**를 뜻한다.

| cout | 의미 |
|---|---|
| **1** | borrow 없음 → `a ≥ b`, 결과가 0 이상 |
| **0** | borrow 발생 → `a < b`, 결과가 음수 |

무부호 비교기로 쓸 수 있다는 뜻이다. `a ≥ b` 판정이 그냥 `cout`이다.

이 프로젝트는 항상 큰 값에서 작은 값을 빼기 때문에 **`cout`이 항상 1**이고,
따라서 정보를 담지 않는다. 크기 비교를 이미 앞단에서 했으므로 중복이다.

### 오버플로는 다르다

| | 조건 | 대상 |
|---|---|---|
| **carry / borrow** | 무부호 범위 초과 | 무부호 연산 |
| **overflow** | 부호 있는 범위 초과 | 부호 있는 연산 |

부호 있는 연산의 오버플로 판정:
```
overflow = cin_MSB ^ cout_MSB
```
MSB 자리의 캐리 입력과 출력이 다르면 오버플로다.

예 (4비트): `0111 + 0001 = 1000` → 7 + 1 = −8. 캐리는 0인데 오버플로.

부호 있는 감산에서는 `a`, `b`의 부호가 다를 때만 오버플로가 가능하다.

## 5. 리플 캐리 가산기와 지연

이 프로젝트의 `generate`가 만드는 구조가 **리플 캐리 가산기(RCA)** 다.

```
ci[0] → FA[0] → ci[1] → FA[1] → ci[2] → ... → FA[N-1] → ci[N]
```

캐리가 LSB에서 MSB로 **순차적으로 흘러야** 한다.

| 항목 | 값 |
|---|---|
| 면적 | O(N) — FA N개 |
| **지연** | **O(N)** — 캐리 체인이 임계 경로 |

N이 커지면 지연이 선형으로 증가한다. 32비트, 64비트에서는 감당하기 어렵다.

### 개선 구조들

| 구조 | 지연 | 방식 |
|---|---|---|
| 리플 캐리 (RCA) | O(N) | 캐리를 순차 전파 |
| **캐리 룩어헤드 (CLA)** | **O(log N)** | G/P로 캐리를 병렬 계산 |
| 캐리 선택 (Carry-Select) | O(√N) | 캐리 0/1 두 경우를 미리 계산해 MUX로 선택 |
| 캐리 스킵 (Carry-Skip) | 개선됨 | 블록 단위로 캐리를 건너뛰기 |

Project 2에서 정리한 G/P 분리가 CLA의 기반이고, Project 10의 FPU가 48비트 가수를 더할 때
CLA를 쓴다. 리플 캐리로는 지연이 너무 커진다.

## 6. generate문

### always의 for와 generate의 for는 다르다

| | `always` 안의 `for` | `generate`의 `for` |
|---|---|---|
| 의미 | **순차 실행** (시뮬레이션 시간 내) | **하드웨어 복제** (구조 생성) |
| 인덱스 | `integer` | **`genvar`** |
| 결과 | 하나의 로직 | 인스턴스 N개 |

```verilog
genvar i;
generate
    for (i=0; i<N; i=i+1) begin : gen_cal   // 블록 이름 필수
        adder FA( ... );
    end
endgenerate
```

**블록에 이름을 붙여야** 한다. 계층 경로가 `gen_cal[0].FA` 형태로 생성되어
파형이나 계층 참조에서 개별 인스턴스를 지목할 수 있다.

### 다른 형태

```verilog
generate
    if (N > 8) begin : big     // 조건부 생성
        ...
    end
endgenerate

generate
    case (MODE) ... endcase    // 케이스별 생성
endgenerate
```

파라미터 값에 따라 구조 자체를 바꿀 때 쓴다.

## 7. parameter

```verilog
module calculate_sub #(parameter N=4)( ... );
...
calculate_sub #(.N(8)) u8( ... );    // 8비트로 인스턴스화
```

| | 특징 |
|---|---|
| `parameter` | 인스턴스화 시 **덮어쓸 수 있다** |
| `localparam` | 모듈 내부 상수. 덮어쓸 수 없다 |
| `` `define `` | 전처리기 매크로. 파일 범위를 넘어 전역 오염 위험 |

비트폭이나 단계 수는 `parameter`, 상태 인코딩 같은 내부 상수는 `localparam`을 쓴다.

## 8. 용어 정리

| 용어 | 뜻 |
|---|---|
| **1의 보수** | 모든 비트 반전 (`~b`) |
| **2의 보수** | `~b + 1`. 현대 정수 표현의 표준 |
| **부호-크기** | MSB를 부호로 쓰는 방식. IEEE-754가 사용 |
| **end-around carry** | 1의 보수 덧셈에서 최종 캐리를 LSB에 다시 더하는 보정 |
| **borrow** | 감산에서의 빌림. 2의 보수에서는 `~cout` |
| **overflow** | 부호 있는 연산의 범위 초과. `cin_MSB ^ cout_MSB` |
| **RCA** | 리플 캐리 가산기. 지연 O(N) |
| **CLA** | 캐리 룩어헤드 가산기. 지연 O(log N) |
| **genvar** | `generate` 전용 인덱스 변수 |
| **parameter / localparam** | 덮어쓸 수 있는 상수 / 내부 전용 상수 |
