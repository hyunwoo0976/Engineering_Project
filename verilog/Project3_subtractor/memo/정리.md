# Project 3 — 정리

2의 보수를 이용해 감산기를 구성. N비트 파라미터화와 `generate`문을 처음 사용.

## 3. 동작 원리

### 감산을 덧셈으로 바꾸기

```
a − b = a + (−b) = a + (~b + 1)
```

`~b`는 1의 보수, 여기에 1을 더하면 2의 보수(−b)가 된다.
그 +1을 별도 가산기로 처리하지 않고 **캐리 입력에 넣는다**.

```verilog
assign ci[0] = 1'b1;    // 이 1이 2의 보수의 +1
```

### 항상 큰 값에서 작은 값을 뺀다

```verilog
wire [N-1:0] val_a = (a>=b) ? a : b;    // 큰 값
wire [N-1:0] pre_b = (a>=b) ? b : a;    // 작은 값
wire [N-1:0] val_b = ~pre_b;            // 작은 값의 1의 보수
```

크기를 먼저 비교해 순서를 바꾸므로 **결과가 음수가 되지 않는다.**
→ 부호 출력이 필요 없고, 결과는 항상 `|a − b|`.

### 리플 캐리 체인

```verilog
wire [N:0] ci;
assign ci[0] = 1'b1;

generate
    for (i=0; i<N; i=i+1) begin : gen_cal
        adder FA(
            .a(val_a[i]), .b(val_b[i]),
            .cin(ci[i]),               // 아래 자리에서 온 캐리
            .sum(sum[i]),
            .cout(ci[i+1])             // 위 자리로 보낼 캐리
        );
    end
endgenerate

assign cout = ci[N];
```

`ci`를 `[N:0]`으로 한 칸 크게 잡아 캐리 체인을 배열로 표현했다.
`ci[0]`이 초기 캐리, `ci[N]`이 최종 캐리.

### 계산 예 (a=10, b=4, N=4)

```
val_a = 1010  (10)
pre_b = 0100  (4)
val_b = 1011  (~4)

  1010
+ 1011
+    1   ← ci[0]
-------
 1 0110   → sum = 0110 (6), cout = 1
```

## 4. 핵심 코드

### parameter로 비트폭 분리

```verilog
module calculate_sub #(parameter N=4)(
    input [N-1:0] a, b,
    output [N-1:0] sum,
    ...
);
```

인스턴스화할 때 폭을 바꿀 수 있다.
```verilog
calculate_sub #(.N(4)) uut( ... );
```

### generate for — 하드웨어 복제

```verilog
genvar i;
generate
    for (i=0; i<N; i=i+1) begin : gen_cal
        adder FA( ... );
    end
endgenerate
```

`always` 안의 `for`는 **순차 실행**이지만, `generate`의 `for`는 **모듈을 N개 물리적으로 복제**한다.
`genvar`로 인덱스를 선언하고, 블록에 이름(`gen_cal`)을 붙여야 계층 경로로 접근할 수 있다.

파형에서 개별 인스턴스를 보려면 `gen_cal[0].FA` 형태로 찾는다.

## 5. 검증 방법

`$monitor`로 값 변화를 콘솔에 출력. 5케이스.

| # | a | b | cin | 결과 | cout | 의도 |
|---|---|---|---|---|---|---|
| 1 | 10 | 4 | 0 | 6 | 1 | a > b |
| 2 | 1 | 14 | 0 | 13 | 1 | **a < b** — 순서 바뀜 확인 |
| 3 | 14 | 8 | 0 | 6 | 1 | a > b |
| 4 | 13 | 13 | 0 | 0 | 1 | **a = b** — 결과 0 |
| 5 | 10 | 4 | 1 | 6 | 1 | cin 영향 확인 |

전부 `|a−b|`와 일치. 실행 결과는 `img_calculate_sub/result.PNG`.

### 확인된 두 가지

**`cin` 포트가 동작에 영향을 주지 않는다.**
case1과 case5는 `a`, `b`가 같고 `cin`만 다른데 결과가 둘 다 6이다.
`ci[0]`이 `1'b1`로 고정되어 있어 포트 `cin`은 아무 곳에도 연결되지 않는다.
→ [error_log R01](error_log.md)

**`cout`은 항상 1이다.**
큰 값에서 작은 값을 빼므로 borrow가 발생할 수 없다.
`a = b`일 때도 `a + ~a + 1 = 2^N`이 되어 `cout = 1`, `sum = 0`.
따라서 이 설계에서 `cout`은 정보를 담지 않는다.

## 6. 배운 것 / 이후 연결

| 개념 | 이후 사용처 |
|---|---|
| **2의 보수 (`~b + 1`)** | ALU 감산, FPU 지수 비교, 부호 처리 |
| **cin에 +1을 태우는 기법** | ALU에서 add/sub를 한 가산기로 처리 |
| **parameter + generate** | N비트 가산기(Project 4), 파이프라인 레지스터, LZD |
| **크기 비교 후 순서 교환** | FPU 덧셈에서 지수가 작은 쪽을 시프트하는 것과 같은 발상 |
| **캐리 체인을 배열로** | Project 4 리플 캐리, Project 10 CLA |
| **파일 목록으로 타 프로젝트 모듈 참조** | 이후 공용 모듈 관리 방식 |

### 남은 개선 사항

- `cin` 포트를 실제로 쓰거나(외부 캐리 입력) 제거
- 부호 있는 감산이 필요하면 크기 비교를 없애고 부호 비트를 별도 출력
- `$monitor`만 있고 자동 판정이 없음 → `sum !== (a>b ? a-b : b-a)` 비교 추가 가능
