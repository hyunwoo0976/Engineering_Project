## 재검토에서 확인한 사항

시뮬레이션을 다시 돌려 확인한 내용. 동작은 정상이지만 설계상 정리할 부분이 있다.

### R01 · `cin` 포트가 어디에도 연결되지 않음

- **[증상]** 테스트벤치 case1과 case5는 `a=10`, `b=4`로 같고 `cin`만 `0`/`1`로 다른데
  결과가 둘 다 `6`으로 동일하다.
  ```
  case1: A=10, B= 4 | Result= 6, Cout=1     ← cin=0
  case5: A=10, B= 4 | Result= 6, Cout=1     ← cin=1
  ```

- **[원인]** `calculate_sub.v:4`에 `input cin`이 선언되어 있지만,
  캐리 체인의 시작값은 `1'b1`로 하드코딩되어 있다.
  ```verilog
  assign ci[0] = 1'b1;    // 2의 보수의 +1. 포트 cin과 무관
  ```
  `generate` 안의 `.cin(ci[i])`는 내부 체인이라 포트 `cin`이 아니다.
  결과적으로 포트 `cin`은 **읽히는 곳이 없는 dead port**다.

- **[영향]** 기능 오류는 아니다. `ci[0]=1`이 감산에 필요한 값이므로 동작은 맞다.
  다만 포트가 있는데 무시되므로, 사용하는 쪽에서 "외부 캐리를 넣을 수 있다"고 오해할 수 있다.
  case5는 아무것도 검증하지 않는 케이스가 되었다.

- **[조치안]** 둘 중 하나
  - 포트를 제거한다 (이 모듈은 감산 전용이므로 외부 캐리가 필요 없다)
  - 또는 `assign ci[0] = 1'b1;` 대신 실제로 활용한다 (add/sub 겸용으로 확장할 경우
    `ci[0] = sub`, `val_b = b ^ {N{sub}}` 형태)

- **[미수정]** 아직 그대로 둠

### R02 · `cout`이 항상 1

- **[증상]** 5개 케이스 전부 `Cout=1`

- **[원인]** 앞단에서 크기를 비교해 **항상 큰 값 − 작은 값**을 계산하므로
  borrow가 발생할 수 없다.
  ```verilog
  val_a = (a>=b) ? a : b;
  pre_b = (a>=b) ? b : a;
  ```
  `a = b`인 경우도 `a + ~a + 1 = 2^N`이 되어 `cout = 1`, `sum = 0`.

- **[영향]** `cout`이 정보를 담지 않는다. 2의 보수 감산에서 `cout`은 원래
  "borrow 없음 = `a ≥ b`"를 뜻하는 유용한 신호인데, 그 판정을 이미 앞단 비교기가 했으므로 중복이다.

- **[조치안]** 크기 비교를 제거하고 2의 보수 결과를 그대로 출력하면
  `cout`이 `a ≥ b` 판정으로 되살아나고 비교기·MUX 2개가 사라진다.
  대신 결과가 음수일 수 있으므로 부호 해석이 필요해진다.

### R03 · 테스트벤치에 자동 판정이 없음

- `$monitor`로 값을 출력하지만 기대값과 비교하지 않는다. 5케이스는 눈으로 볼 수 있으나,
  기대값을 식으로 만들 수 있는 경우라 자동화가 쉽다.
  ```verilog
  if (sum !== ((a>=b) ? a-b : b-a)) $display("[FAIL] a=%d b=%d sum=%d", a, b, sum);
  ```

## 교훈

1. **선언한 포트가 실제로 읽히는지 확인한다.** `input`은 미연결이어도 컴파일 경고가 나지 않아
   조용히 dead port가 된다 (R01)
2. **항상 같은 값이 나오는 출력은 의심한다.** 정보를 담지 않는 신호이거나
   앞단 로직과 중복된 판정일 가능성이 높다 (R02)
3. **입력만 바꾸고 결과가 같은 테스트 케이스는 아무것도 검증하지 않는다.**
   case1/case5가 그 예 — 기대값을 미리 계산해봤다면 같은 값이 나올 것을 알 수 있었다
